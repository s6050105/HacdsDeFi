协议概览

hacds 是运行在 Hacash 主网上的 DeFi 协议。它把 HACD 钻石的评分转化为同质化代币 hacds，并围绕这个代币构建了兑换、做市、借贷三套金融原语。

设计目标

上一版把 hacds 做成刻在钻石上的铭文，导致代币无法拆分、无法自由流通。这一版的核心改动只有一条：把币从钻石上拿下来。

hacds 现在是标准的 Hacash 链上资产：可自由转账、可拆分、可在 AMM 里交易。钻石只作为铸造它的凭证，不再承载它。

三个组成部分

组件职责位置
合约持有全部资产与账本，执行兑换/借贷/赎回Hacash 主网 HVM

新版设计已移除预言机：HACD 评分改由合约链上直读基因计算，不再依赖链下签名证书。

系统架构

整个协议只有一个合约地址，所有状态都在其中。没有管理员，没有升级入口，没有自毁函数。

职责边界

  • 合约 — 唯一的事实来源。所有余额、债务、池子状态都在链上。
  • 钱包 — 只管签名。私钥从不离开用户设备。
  • 官网 — 只构建交易体，不碰私钥，不保存任何用户数据。
  • 索引器 — 只读，默认以 --read-only 运行。 合约无法枚举地址，索引器扫链补上「谁借了款、池里有哪些钻石」这类列表能力； 另外提供 /backing（合约内部积分 vs 真实链上余额）供运维监控。 它不参与任何资金逻辑——索引器宕机只影响列表展示，不影响用户取回资产。
与 #2000 的架构差异

上一版（#2000）有预言机：链下算分后签一张 126 字节证书，合约再重算比对。 这带来两个问题——预言机是单点，它下线兑换就停；且持有预言机私钥即可影响发分。

#3000 整条证书链路都删掉了，也没有 init_admin / set_paused / set_oracle 这类管理员入口。评分改由合约通过 HVM 内置 hacd_info 直接读钻石基因、本地自算。 架构上少了一个组件，也少了一个可被攻击的信任点。

AMM 兑换

恒定乘积做市（x × y = k），费率 0.5%，从输入腿收取。

报价公式

输入 amt，扣费后 net = amt × (1 − 0.005)
输出 = pool_out × net / (pool_in + net)

滑点保护

所有兑换与流动性操作都带 deadline（块高）和 min_out / min_share 参数。任一不满足则整笔回滚，防止被抢跑。

利率模型

U ≤ 35%:  rate = 2% + 4% × U / 35%
U > 35%:  rate = 6% + 40% × (U − 35%) / 15%

U = 利用率 = 总债务 / HAC 提供者总量
U=0 → 2%   U=35% → 6%   U=50% → 46%

清算

抵押率跌破 160% 后，任何人可发起清算。清算人支付真 HAC，按「付款额 + 5% 奖励」的价值获得对应抵押品。

注意：抵押品交割按付款额计算，不按债务比例。按债务比例会在 160% 抵押率下让清算人拿走借款人几乎全部权益。

HACD 铸造与赎回

铸造（存入 HACD）

存入 1 颗 HACD，按评分铸造 hacds，不打折（MINT_HAIRCUT_BPS = 10000，即 100%）。 换算比例是 1 分 = 1 亿 hacds，不是 1 分 = 1 hacds。

score = score_of(diamond_name)      // 原始分，整数，约 3.55 分平均
mint  = score × SCORE_SCALE         // SCORE_SCALE = 1e8，100%，无折扣

例：一颗 3 分的钻石
  mint = 3 × 100,000,000 = 300,000,000 hacds

为什么是 1e8：发行总量 5.96e15 个 hacds 与这套定标配套 —— 全网均分 3.5544 乘以 HACD 总数 16,777,216，得 59,632,987 分，再乘 1e8，正好是 5,963,298,700,000,000。 若 1 分只铸 1 个，总量就只有 5963 万，与 decimal=0 下的供给对不上。

赎回（取出 HACD）

支付 hacds 换回一颗 HACD。基础手续费 0.5%（REDEEM_FEE_BPS = 50）； 若该钻石评分高于池内均分，额外收取「挑钻石溢价」。

gross   = score × SCORE_SCALE
avg     = 池内总分数 / 颗数
premium = min(30%, (gross − avg) / avg)      // 只对高于均分的收
fee     = gross × 0.5% + gross × premium
charge  = gross + fee                        // 实际扣的 hacds

溢价上限 30%（CHERRY_PREMIUM_MAX_BPS = 3000）， 防止有人反复从池子里挑走高分钻石、把低分货留给其他持有人。

配额不足会自动补足

赎回要扣的 charge 超过你账上的 hacds 配额时，合约会自动拿你的 HAC 经 AMM 换成差额的 hacds（内部调用 swap_hac_to_ds 原语），不需要你手动先换。 兑换按当时池价执行，含 0.5% 兑换费——所以赎回前先看清楚价差是否划算。 若 HAC 也不够，整笔返回 12 回滚。

池内必须有记录

池里没有 HACD（res:hacd_count = 0）或账面分数不足以覆盖本次赎回时， 返 61 回滚。这是防下溢的保险，正常路径不会触发。

评分机制

HACD 评分基于 5 个算法函数，但每次实际只用其中 4 项相加—— 「样式」与「颜色」是互斥的：

total = 形状 + (Common ? 样式 : 颜色) + 命名 + 编号
if total < 1 { total = 1 }        // 保底 1 分
项说明取值依赖
形状Square / Heart / Circle 等 8 种visual_gene[0..2]
样式 （仅 Common）Common 形状才参与visual_gene[2..18]
颜色 （仅非 Common）名字首字母 + 明暗加成visual_gene + name
命名6 字母的重复 / 对称加成diamond name
编号顺子、对称数字加成diamond number
链上直读，无预言机

合约通过 HVM 内置 hacd_info(name) 直接读取钻石的基因与编号， 然后在链上自算分。整条证书链路（链下算分 → 签名 → 链上重算比对）已删除。 这消除了「谁持有预言机私钥谁就能影响发分」的风险，也去掉了预言机这个单点故障。

对比 #2000：那一版由预言机在链下算分、签一张 126 字节证书， 合约再重算比对。预言机下线兑换就停，且它本身是可信第三方。

「1 分」到底是多少

合约内部 score 是原始整数分（平均约 3.55）。铸发时乘 SCORE_SCALE = 1e8，所以 1 分 = 1 亿个 hacds。 文档、页面、钱包里凡是提到「分数」的地方，都要区分清楚是原始分还是已乘标度的 atoms。

风险说明

智能合约风险

合约不可升级。一旦部署，任何漏洞都无法修补。请只投入你能承受损失的资金。

价格与清算风险

hacds 价格完全由 AMM 池子决定。池子较浅时，大额交易会产生显著滑点。抵押借贷在价格下跌 20% 后可能被清算。

流动性风险

极端行情下，AMM 池子可能被单向抽干，导致兑换失败或撤池受限。

评分算法风险

HACD 评分基于主观维度（形状、颜色、命名）的量化规则。若评分标准与市场共识偏离，会影响 hacds 的内在价值支撑。
