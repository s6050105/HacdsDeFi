## 1. 先准备三样东西

**一台电脑**（Windows 64 位）**或一台安卓手机**。

| 平台 | 文件 | 说明 |
|---|---|---|
| PC | `HacdsDeFi-Setup-0.4.4-x64.exe` | 安装版，双击装好 |
| PC | `HacdsDeFi-0.4.4-x64.exe` | 免安装版，双击直接运行 |
| 安卓 | `HacdsDeFi-0.2.4-arm64.apk` | 需允许"安装未知来源应用" |

PC 两选一即可。手机只支持 arm64（近年所有主流机型）。

**能连上服务器。** 钱包本身不存链上数据，它要连两个服务：

| 服务 | 地址 | 干什么 |
|---|---|---|
| 节点 | `node.hacds.com` | 查余额、广播交易、读合约状态 |
| 索引器 | `indexer.hacds.com` | 借贷清算用的台账（可选） |

这两个地址已经填好了，网络通就不用改。如果要换，在顶部改。

> **只有两个服务，没有预言机了。** 旧版还有一个"给钻石出评分证书"的服务，
> 那个已经整个删除——现在合约自己读钻石基因算分，不需要任何链下环节。

## 3. 建钱包（或导入已有的）

### 3.1 新用户：创建钱包

点「创建钱包」，设一个口令。

**口令至少 8 位，丢了就找不回来。** 钱包文件加密后存在本机，没有"找回"功能，
没有客服，没有后门。请写在纸上，别只存在电脑里。

创建完成后会显示你的地址（`1` 开头，约 34 位）。

**立刻备份。** 钱包的恢复**只有两条路**：导出 keystore 文件（推荐，加密、
需要口令）或导出私钥（明文，风险高）。没有助记词，也没有任何服务端备份 ——
本机钱包文件丢了、卸载了应用，又没导出过，这笔钱就找不回来了。

### 3.2 已有钱包：两种导入方式

| 方式 | 用在哪 |
|---|---|
| Keystore 文件 | **推荐**。PC 和安卓互通，格式一样（`hacds-keystore v1`） |
| 私钥 | 有历史遗留私钥、或只想快速导入时用（明文，注意别泄露） |

> ⚠ 本钱包**不支持助记词**（没有 12 个单词那种恢复方式）。
> 如果你习惯用助记词管理资产，请在外面生成好钱包、再用它的**私钥**导入。

### 3.3 管多个钱包

点「钱包管理」能看到本机所有钱包，切换、重命名、删除都在这里。

顶部是**七个页签**，和网页版完全一致：

[兑换] [流动性] [借贷] [HACD] [转账] [资金] [工具]

下面三张常驻卡片：

| 卡片 | 内容 |
|---|---|
| 资产总览 | HAC、HACD 颗数、hacds 余额、合约内配额 |
| 协议状态 | 池子两侧储备、参考价、借贷利用率 |
| 借贷状态 | 你的债务、抵押、健康度 |

三张都可以点右上角的 `▾` 折叠。

## 5. 三张卡怎么读

### 5.1 资产总览

| 项 | 含义 |
|---|---|
| HAC | 钱包里能直接花的 HAC |
| HACD | 你持有的钻石颗数 |
| hacds（配额） | **合约内**账面上的 hacds，还没领到链上 |
| hacds（链上） | 已经在你自己地址里的标准资产 |

**两个 hacds 相加才是你真正拥有的全部。**

### 5.2 协议状态

| 项 | 含义 |
|---|---|
| 池 HAC / 池 hacds | AMM 池子两侧的储备 |
| 参考价 | 合约用来清算估值的平滑价格 |
| 利用率 | 已借出 / 可出借，超过 50% 不能再借 |

### 5.3 借贷状态

**健康度**这一栏最重要：

| 显示 | 状态 | 会发生什么 |
|---|---|---|
| > 10000 | 安全 | 什么都不会发生 |
| = 10000 | 危险 | 正好在清算线上 |
| < 10000 | 可清算 | 任何人可以随时清算你 |
| < 10500 | 深水 | 清算人可以接管（`DEEP_TRIGGER_BPS = 10500`） |
| < 9000 | 深度危险 | 允许**一次清完全部债务**（`DEEP_WATER_BPS = 9000`） |

**这两个阈值不是一回事，别混：**

- **10500（105%）** 是「抵押价值 / 债务」的比较，触发后清算人拿 3% 折扣接管
- **9000（90%）** 是「健康度」，跌破后清算不受"只能清一部分"的限制，可以整笔清完

合约里的常量是 `DEEP_TRIGGER_BPS = 10500` 和 `DEEP_WATER_BPS = 9000`，两处都有。

**没有宽限期。** 跌破 160% 抵押率就随时可被清算，不会提前通知你。

## 6. 每笔交易都是同一套动作

不管做什么，流程都一样：

```
填参数 → 点「生成交易」 → 看预览 → 点「广播」 → 等上链
```

**预览区会显示**：动作、字节数、手续费、签名摘要。

**广播之后的三种结果**：

| 结果 | 意思 |
|---|---|
| `ret:0` | 进了内存池，**还没上链** |
| 上链了 | 余额会变 |
| 报错 | 看日志，中文说明 |

**出块约 300 秒。** 广播成功不等于立刻生效，钱包会自动补刷几次（15/45/90/180/320 秒）。

## 7. 常见操作怎么做

### 7.1 把钻石换成 hacds（最常用）

1. 点「HACD」页签
2. 点「加载我的钻石」
3. **勾选你要存的钻石**——可以一次勾很多，最多 200 颗
4. 点「批量存入兑换」

**一次交易、一次签名，最多 200 颗。** 这是这一版最大的改动：旧版一次只能存 1 颗。

界面会显示预计铸出的 hacds 数量：**1 分 = 1 亿 hacds**。

> **注意**：存入之后你拿到的是**合约内的配额（due）**，还不是链上资产。
> 要拿到链上钱包里，看 7.2。

### 7.2 把 hacds 领到手

点「资金」页签 → 「领取 hacds」→ 填数量 → 生成 → 广播。

**这一步才把 hacds 真正转进你的地址。** 领到之后，它就是一个标准的链上资产，
可以转到任何支持 Hacash 资产的钱包或交易所。

### 7.3 充 HAC 进合约 / 提出来

「资金」页签：

| 操作 | 做什么 |
|---|---|
| 充 HAC | 钱包里的 HAC → 合约内的 HAC 积分（用来加流动性、还款） |
| 提 HAC | 合约内积分 → 钱包 |
| 充 hacds | 链上 hacds → 合约内配额（用来加流动性、抵押） |
| 领 hacds | 合约内配额 → 链上 |

**注意区分**：合约内的是"积分"，链上的是"资产"。两者不是一回事，
AMM 和借贷操作的都是**合约内**的那份。

### 7.4 在池子里换币（AMM）

「兑换」页签，两个方向：

| 操作 | 填什么 |
|---|---|
| HAC → hacds | 投入 HAC（单位 HAC） |
| hacds → HAC | 投入 hacds（单位：个） |

输入后下方会实时显示**能换到多少**和**当前池价**。

**滑点保护**：`min_out` 填你能接受的最少得到量，`0` = 不限制。
行情波动大时建议填个数，防止被别人抢跑。

### 7.5 加流动性赚手续费

「流动性」页签。

填 HAC 侧数量，**hacds 侧会自动按池内比例算出来**。这是防止你配错比例白送钱。

| 事项 | 说明 |
|---|---|
| 手续费分成 | 交易费的 **80% 给 LP**，20% 进金库 |
| 赎回费分成 | 赎回手续费的 **80% 也给 LP** |
| 无常损失 | 有。这是所有 AMM 的固有特性 |
| 信用风险 | 池里 30% 的 HAC 被借出去，最坏情况损失这 30% |

**撤池要分两步**：先「领取 LP 奖励」，再「撤出流动性」。
钱包会自动帮你拆成两笔，你点一次就行。

> 为什么要拆？单笔会撞主网 resource 桶上限（6,102 > 6,100）。
> 这是实测出来的坑，合约改不了，只能在钱包侧拆。

### 7.6 抵押借币

「借贷」页签。

1. 先「追加抵押」，抵押的是**合约内的 hacds 配额**
2. 再「借出」，最多借抵押价值的一半

**输入框下方会实时显示**：当前可借上限、这笔需要的抵押、当前抵押价值。
不用试错。

**利率是浮动的**：利用率 0% → 2%，35% → 6%，50% → 46%。

**还不上会被清算。** 没有宽限期。建议：
- 别借满（借 30%–40% 比借满从容得多）
- 健康度到 150% 附近就补仓
- 盯「借贷状态」卡里的健康度，它和链上清算用**同一个价格**

### 7.7 把币转给别人

「转账」页签，四种：

| 类型 | 说明 |
|---|---|
| 转 HAC | 链上 HAC |
| 转 hacds | 链上 hacds 资产 |
| 转 HACD | 钻石，可以一次多颗 |
| 转其它资产 | 填 serial + 数量 |

> hacds 的 serial 是 **4000**，股权（HACDS-SHARE）是 **4001**。
> 别填成旧版的 2000 / 3000——那两套资产已经作废，转过去对方也认不出值，等于白转。

### 7.8 HACD 页：看钻石、批量操作

「HACD」页签上下两块：

**上半：存入**
- 加载我的钻石 → 勾选 → 批量存入
- 单笔最多 200 颗

**下半：赎回**
- 加载池内钻石 → 选一颗 → 赎回
- **赎回只能一次一颗**

> 为什么赎回不能批量？赎回要给每颗钻石单独算「挑钻石溢价」（高分钻石多付钱），
> 而且批量操作一旦中途失败，回滚逻辑在不可升级的合约里风险太高。
> 钱包会自动把你选的拆成多笔，你点一次即可。

## 8. 进阶功能（不看也能用）

### 8.1 只读查询

「工具」页签 → 「只读查询」。可以直接调合约的任意只读函数，看返回值。
排查问题时很有用。

### 8.2 原子交易

多个动作并进一笔交易，要么全成要么全败。协议上限 200 个动作。

### 8.3 离线签名（冷热分离）

「工具」页签 → 「离线签名」：

1. 冷端（不联网的机器）填参数、生成、签名
2. 输出二维码或文件
3. 热端（联网机器）扫码或读文件，广播

**私钥全程不触网。** Hacash 的交易没有 nonce、没有时间戳过期，
离线签好的交易放很久再广播依然有效。

### 8.4 清算 / 结算

「工具」页签 → 「清算」。列出所有可清算的地址和健康度。

清算是有钱赚的：你替别人还债，拿走「还款额 + 5%」的抵押品。
普通清算单次最多处理对方一半债务。

### 8.5 续租存储键（运维）

「工具」页签 → 「续租」。

Hacash 的合约状态要付租金，键到期会失效。**任何人都能续租，还能拿到报酬 （0.07 HAC/键）**。keeper 就是这么工作的。

普通用户可以不管——项目方的 keeper 会自动续。

## 9. 金库分红（持有股权的人必看）

如果你持有 **serial 4001（HACDS-SHARE）**，钱包会自动多出一个「金库分红」页签，金色高亮。

### 9.1 最重要的一件事：持有 ≠ 分红

**钱包里揣着 4001 不会自动分红。必须质押进合约 B 才开始计息。**

为什么这样设计：用户 A 把 4001 转给用户 B，这个动作在链上完全不经过合约 —— 合约看不到。它无法在"卖出的那一瞬间"结算，所以只能要求你**主动质押**，让份额进入合约账本（`sh:<你的地址>`），合约才认。

页签里会明确区分：

| 字段 | 含义 |
|---|---|
| 钱包持有 | 你钱包里还有多少份 |
| 已质押（计息中） | 真正参与分红的份数 |
| 未质押（不计息） | 还在钱包里、**不分红**的份数 |

**只要「未质押 > 0」，页签下方就会出现醒目提示**，告诉你这部分不参与分红，并给一个「立即质押」按钮。

### 9.2 三步操作

**① 质押**

点「立即质押」→ 输入份数 → 确认。

⚠ 确认框会明确告诉你：**这会把 N 份股权转入金库合约，转出后不再显示在钱包余额里，但仍属于你，可随时赎回。**

这是转账，不是"存入"。份额会离开你的钱包余额，进入合约账本。所有权不变。

**② 等分红累积**

协议收入（AMM 手续费分成、借贷利息分成等）会归集到金库合约 B
（地址 `duEkx1E3owCP2VhTq6LzvLUGeMJpjZXm4`，可以在浏览器上查它的余额与分配记录）：

```
收到 100 HAC
  ├─ 20 HAC → 续租储备（只用于支付 keeper 的存储续租）
  └─ 80 HAC → 按份额分给所有质押者
```

分红按你的份额占「已质押总量」的比例计算。质押得越多、质押得越早，分得越多。

**③ 领取并提现**

点「领取并提现」，一步完成：

```
claim()                  → 把增量结算进你的 due 账本（钱还在合约里）
TransferHacFromTo(B→你)  → 钱真正到你的钱包
```

两步必须都做。**只点 claim 的话，钱还在合约里，你的钱包余额不会变。**

⚠ **页签里的「总计可提取」在 claim 之后数值不变** —— 因为增量从"未结算"变成了"已结算待提现"，总数没变。这不是 bug。

### 9.3 赎回质押

想拿回份额，点「赎回质押」。合约会：

1. 先结算你到此刻为止的分红
2. 再把份额从账本扣掉
3. 4001 回到你的钱包余额

顺序不能反 —— 先结算再减份额，保证你退出前的分红一分不少。

### 9.4 常见误解

| 你可能以为 | 实际 |
|---|---|
| 持有 4001 就有分红 | ❌ 必须质押 |
| 质押后份额就没了 | ❌ 只是搬进合约账本，随时可赎回 |
| 点了 claim 钱就到账了 | ❌ 还要提现那一步 |
| claim 后数字没变是 bug | ❌ 是"未结算"转成了"待提现" |
| 不领就会过期 | ❌ 分红一直记在合约里，不会被收回 |

### 9.5 忘了来领会不会丢

不会。分红一直记在你的 `due:` 账本里。

但有个前提：**账本键必须有人续租**。合约的存储键是租用制，到期会被删除。项目方的 keeper 会自动帮你续（每 347 天一次），所以正常情况不用管。

如果你希望更保险，**偶尔来点一次「领取并提现」** —— 这个动作本身会顺带把你的键续上。

## 10. 股权转让（OTC 原子交易）

想把 4001 卖给别人，用「金库分红」页签最下方的**「股权转让」**区域。

### 10.1 为什么需要两个人签名

一笔交易里同时包含"你给股权"和"他给钱"，双方都得同意。Hacash 的规则是**签名数必须等于签名者数**，所以：

```
你（卖方）构建交易 + 签名
        ↓
    把交易体发给他（微信/邮件/二维码都行）
        ↓
他用自己的钱包"翻译"这份交易，看清内容
        ↓
    他确认无误 + 追加签名
        ↓
      广播，双方资产同时变动
```

**交易要么全部成交，要么全部回滚。** 不会出现"给了股权没收到钱"。

### 10.2 卖方怎么操作

1. 在「股权转让」区域选「我卖出股权」
2. 填股权份数、对手方地址
3. 选对价（最多 3 种：HAC / 链上资产 / HACD 钻石）
4. 点「生成待签名交易」
5. 点「用我的私钥签名」→ 提示"未签齐"，把交易体复制发给他

### 10.3 买方怎么操作（重要）

**先看清，再签名。** 这一节是整个功能里最关键的。

1. 打开「股权转让」区域的「核对他人的交易体」
2. 粘贴对方发来的交易体
3. 点「翻译这份交易」
4. **逐项核对**：
   - 「你将付出」的金额对不对
   - 「你将收到」的份数对不对
   - **收款地址是不是你**（这一行会高亮，不是你会有红色警告）
5. 确认无误后，点「给对方交易体追加我的签名」
6. 签齐后会自动广播

⚠ **没翻译过就不允许签名** —— 这是防止盲签的硬性限制。

### 10.4 ⚠ 交易体没有有效期

这是最需要注意的一点：

**你签名后把交易体交给对方，这笔交易随时可能被广播，无法撤回。**

链上没有"过期时间"这个字段。所以：

- 只跟你完全信任的人做 OTC
- 谈崩了要立刻让对方销毁交易体
- 不要为了"先看看"就签名

## 11. ⚠ 数字怎么看（最容易出错的一节）

### 11.1 hacds 就是个数

**这一版 hacds 是 decimal 0 —— 1 就是 1 个，没有小数。**

余额、池子、抵押、输入框，看到的都是同一个数字。

```
想转 70 个 hacds → 输入框填 70
```

> **和旧版不同！** 旧版（#2000）是 decimal 8，那时输入框填的是 atoms，
> 要填 `7000000000` 才是 70 个。**这一版不要乘 1e8。**

### 11.2 HAC 也是个数

标签写「（HAC）」的地方，想充 10 个 HAC 就填 `10`。

**例外**：链上转账页的 HAC 金额要写成 `1:248` 这种格式（`1:248` = 1 HAC）。
这是 Hacash 的金额写法，照输入框默认值的样式改就行。

> `a:b` = a × 10^(b−248)。所以 `5:249` = 50 HAC，不是 5.0038。

### 11.3 对照表

| 你要操作 | 填什么单位 | 例子 |
|---|---|---|
| 加流动性 —— HAC 侧 | HAC | `1` |
| 加流动性 —— hacds 侧 | 个数 | 按池内比例**自动算出**（不是固定值） |
| 换币 —— 投入 HAC | HAC | `1` |
| 换币 —— 投入 hacds | 个数 | `100000000` |
| 追加抵押 | 个数 | `100000000` |
| 借出 / 还款 | HAC | `0.5` |
| 转 hacds | 个数 | `100000000` |
| 转 HAC（链上） | `值:尾数` | `1:248` |

**记住一句话**：hacds 填个数，HAC 填 HAC 个数（链上转账除外）。

### 11.4 为什么容易搞错

HAC 和 hacds 的量纲不同：

- **HAC** 链上是 zhu，1 HAC = 1e8 zhu，界面上用 HAC
- **hacds** 链上就是个数，1 = 1 个

所以 `add_liquidity(hac_amt, ds_amt)` 两个参数的单位不一样：一个是 zhu，
一个是 hacds 个数。这是最容易犯 1e8 倍错误的地方——我们自己在首注时就犯过一次。

## 12. 出问题了怎么办

### 12.1 先看日志区

所有操作的结果、失败原因都打在底部日志区。**报错是中文的**，
先说是什么问题，再给建议。

### 12.2 常见报错

| 你看到的 | 什么意思 | 怎么办 |
|---|---|---|
| 余额不足 | 合约内积分不够 | 先去「资金」页充值 |
| `resource gas limit exceeded` | 单桶 gas 超限 | 拆成多笔；**提高 gas_max 无效** |
| `compute gas limit exceeded` | 同上 | 拆成多笔 |
| `CallNotExist(51)` | 合约没这个函数 | 管理员函数已全部删除，别点了 |
| `NotFindContract` | 该地址没有合约 | 地址填错（本轮合约是 `bw2sRC…`） |
| `StorageNotActive` | 存储键过期 | 去「工具」页续租 |
| `state changed` | 期间链上状态变了 | 重试 |
| `sandbox_per_ip_concurrency_exceeded` | 并发超限 | 等几秒重试（节点限制每 IP 2 个并发） |
| 网络错误 | 服务连不上 | 检查节点地址和网络 |

### 12.3 广播成功但余额没变

正常。出块约 300 秒。等一会儿点「刷新资产」。

### 12.4 界面字太小 / 太大

顶部 `−` / `+` 调，`⟲` 复位。

### 12.5 三张卡可以收起来

点卡片右上角的 `▾`。

## 13. 安全须知

1. **导出 keystore 或私钥后离线保存，口令也要记住。** 没有找回功能，没有客服；
   本钱包不支持助记词，丢了口令又没有导出，钱就没了。
2. **别把全部身家放进来。** 合约不可升级，发现 bug 也改不了。
3. **股权的持有是单点。** 合约里没有提款函数，没人能拿走你的资产；
   金库收入按质押份额自动分配（见第 9 章），分配过程由代码保证、无人可干预。
   但 **10,000 份 4001 目前全部由项目方分发持有** —— 这是唯一需要信任他们的地方：
   他们手里有多少份额，就有多少分红权。
4. **没有管理员。** 没有任何人能暂停合约、改参数、冻结你的账户。
   这一点可以从函数清单直接验证。
5. **官方不会主动私聊你。** 任何要你"验证钱包""发送助记词"的都是骗子。
6. **离线签名时，私钥全程不触网。** 冷端机器最好永久断网。

## 14. 一些术语的通俗解释

| 名词 | 人话 |
|---|---|
| **hacds** | 把钻石存进合约后得到的代币，1 分钻石 = 1 亿个 |
| **HAC** | Hacash 主币，就是能花的钱 |
| **HACD** | 钻石，存进合约能换 hacds |
| **due / 配额** | 合约账面上记给你的 hacds，还没领到链上 |
| **AMM** | 自动做市，一个池子，谁都能来换，价格自动调 |
| **LP** | 流动性提供者，把钱放进池子赚手续费的人 |
| **滑点** | 你的交易把价格推动了多少，大额交易滑点大 |
| **抵押率** | 抵押品价值 ÷ 债务，200% 是借款线，160% 是清算线 |
| **健康度** | 抵押率的另一种写法，10000 = 正好在清算线上 |
| **清算** | 你还不上钱，别人替你还，拿走你一部分抵押品 |
| **深水** | 抵押价值跌破债务的 105%（`DEEP_TRIGGER_BPS`），清算人可接管 |
