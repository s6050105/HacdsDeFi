# hacds.com 官网 · 部署指南

> 适用版本：#3000（合约未部署时也可先上线，页面会显示「未部署」状态）
>
> **这是一个纯静态站**，没有构建步骤。但写操作依赖 Cloudflare Worker 反代。

---

## 0. 先理解架构

```
浏览器 ──HTTPS──► hacds.com                （Worker「hacds」，静态资源托管）
   │
   └──HTTPS──► api.hacds.com               （Worker「hacds-api」，反向代理）
                   │
                   ├──► 节点    http://43.251.101.101:8082   读链上数据
                   ├──► 索引器  http://43.251.101.101:8124   读台账 / /backing
                   └──► 构建服务 http://127.0.0.1:8125       写操作（可选）
```

**为什么必须用 Worker**：后端三个服务都是 **明文 HTTP 且无 CORS 头**，
而官网是 HTTPS。浏览器会以「混合内容」+「CORS」双重原因拦截。
Worker 负责补 HTTPS、补 CORS、转发到后端。

**顺序**：① Worker → ② 静态站 → ③（可选）后端服务

## 1. 部署 Cloudflare Worker（必须先做）

### 1.1 创建 Worker

方式 A —— Dashboard 粘贴：

1. Cloudflare Dashboard → **Workers & Pages** → **Create** → **Worker**
2. 命名 `hacds-api` → Deploy
3. **Edit code** → 全选删除 → 粘贴 `worker/index.js` 全文 → **Deploy**

> 已在 2026-10-27 用这种方式部署成功（版本 `661b01d2`）。
> 唯一麻烦是要手动全选粘贴；国内网络下 Dashboard 的代码编辑器
> 偶尔加载不出来（原因见 §2.3），此时直接用方式 B。

方式 B —— wrangler CLI：

```bash
cd hacds.com/worker
npx wrangler deploy index.js --name hacds-api
```

### 1.2 配置环境变量

Worker → **Settings** → **Variables and Secrets**，添加：

| 变量 | 值 | 必填 |
|---|---|---|
| `NODE_ORIGIN` | `http://43.251.101.101:8082` | ✅ |
| `INDEXER_ORIGIN` | `http://43.251.101.101:8124` | ✅ |
| `BUILD_ORIGIN` | `https://build.hacds.com` | 写操作用，见 §4 |
| `ALLOWED_ORIGINS` | `https://hacds.com,https://www.hacds.com` | 可选（默认即此值） |

> ⚠ `NODE_ORIGIN` / `INDEXER_ORIGIN` 是 **http://**，不是 https。
> Worker → 后端这一段是 Cloudflare 内部出网，不受浏览器混合内容限制。

### 1.3 绑定自定义域名

Worker → **Settings** → **Domains & Routes** → **Add** → **Custom domain**：

```
api.hacds.com
```

前提：`hacds.com` 的 DNS 已托管在 Cloudflare（本域名已是，NS 为
`tricia.ns.cloudflare.com` / `matteo.ns.cloudflare.com`，状态 Active）。

### 1.4 验证

```bash
# ① 不碰后端的路由 —— 用来判断 Worker 本身是否健康
#    未配 BUILD_ORIGIN 时应返回 502 + 可读 JSON，这就说明 Worker 活着
curl -s -X POST https://api.hacds.com/api/build \
  -H 'Content-Type: application/json' -d '{"fn":"lp_harvest"}'
# 期望：{"error":"build_service_unconfigured","message":"交易构建服务尚未部署。…"}

# ② 转发到节点的路由 —— 需要后端真的在跑
curl -s https://api.hacds.com/vm/status
curl -s https://api.hacds.com/api/watchlist
```

**2026-10-28 实测**：① 通过（502 + 正确 JSON，且响应头带我们自己的
`Access-Control-Allow-Origin: https://hacds.com`）。
② 返回 `error code: 1003` —— 这是 **Cloudflare 连不上源站**，
不是 Worker 的问题。经排查，`43.251.101.101` 只有 3389 端口通，
22/80/443/8082/8124 全部拒连，ping 却正常（47ms）。属于后端侧状态，
服务起来后 ② 自然通。

## 2. 部署静态站（Workers Static Assets）

> **2026-10-28 实测**：Cloudflare 已把 Pages 并入 Workers。现在新建的
> 「Pages 项目」实际就是带 `assets` 的 Worker，`wrangler pages deploy` 会
> 自动转成 `wrangler deploy`。下面的流程是**实际跑通的那一套**。

### 2.1 千万别直接 `cd hacds.com` 部署

仓库根目录有个 `wrangler.jsonc`，里面：

```jsonc
{ "name": "hacds-server-main", "assets": { "directory": "hacds.com" } }
```

如果直接 `cd hacds.com && wrangler deploy`，wrangler 会**向上找到根目录的
`wrangler.jsonc`**，把整个 `hacds.com/` 目录（**包括 `worker/index.js`、
`README.md`、`部署指南.md`**）全部当静态资源上传 —— 源码就公开了。

实测确认过：第一次部署后 `https://hacds.com/worker/index.js` 返回 200。
必须改用隔离目录。

### 2.2 正确做法：用 `deploy-site/` 脚本

已经封装好了，别手写：

```bash
cd /d/hacds_server-main/hacds.com

bash deploy-site/build.sh            # 只摊，输出到 deploy-site/.build/
CLOUDFLARE_ACCOUNT_ID=9dfd2a5ab648b9a7b57078df932aeb48 \
  bash deploy-site/build.sh --deploy # 摊完直接部署
```

脚本做三件事：

1. **白名单拷贝** 27 个文件到 `.build/public/`（不用通配，避免将来加了新文件被误传）
2. **自检**：如果 `worker/`、`README.md`、`部署指南.md`、`wrangler.jsonc`
   任何一个出现在 `public/` 里，直接报错退出
3. 在 `.build/` 里生成**独立**的 `wrangler.jsonc`，`assets.directory` 指向 `./public`

要公开的静态文件：

| 路径 | 说明 |
|---|---|
| `index.html` | 首页 |
| `app/index.html` | 协议控制台 |
| `docs/index.html` | 文档页 |
| `whitepaper/` | 白皮书 md + pdf（中文/英文 PDF，三语 md） |
| `assets/css/` | 3 个样式表 |
| `assets/js/` | 8 个脚本（含 `config.js`） |
| `assets/img/` | 4 个图标 |
| `_headers` | 安全头 + 缓存策略 |

**不公开**：`worker/`（已是独立 Worker）、`README.md`、`部署指南.md`、
`deploy-site/` 本身。

> `.build/` 已加入 `tools/sync_to_release.sh` 的排除规则，不会进公开仓库。

### 2.2.1 站点 Worker：`deploy-site/worker.js`

静态站不只是一个 assets 包，前面还有一层 Worker，负责：

- `http://` → `https://` **301**
- `www.hacds.com` → `hacds.com` **301**（避免重复内容）
- 补安全头（`X-Content-Type-Options` / `Referrer-Policy` /
  `X-Frame-Options` / `Permissions-Policy` / `Cross-Origin-Opener-Policy`）

**为什么不交给 Cloudflare 的「Always Use HTTPS」**：那是 zone 级设置，
需要 `zone_settings:edit` 权限。wrangler 的 OAuth token 只有 `zone:read`，
调 API 返回 `10000 Authentication error`。放 Worker 里效果一样，还跟着代码走。

> ⚠⚠ **`wrangler.jsonc` 里必须有 `"run_worker_first": true`。**
> 不加的话静态资源会**直接命中** assets、**绕过 Worker** ——
> 现象很有迷惑性：页面能开、`_headers` 也生效，但重定向完全不触发。
> 2026-10-28 实测踩过一次，排查了半天。

### 2.3 登录 wrangler（只需一次）

```bash
npx wrangler@4 login
```

浏览器会打开授权页，点 **Authorize** 即可。凭据存在：

```
%APPDATA%\xdg.config\.wrangler\config\default.toml
```

> ⚠ **国内网络注意**：`dash.cloudflare.com` 的 SPA 依赖
> `*.workers.dev` 域名的资源，该域名在国内被墙。表现为控制台页面
> 一直白屏、`page.goto` 超时、控制台报
> `ERR_CONNECTION_REFUSED ...workers.dev`。
> **不要以为是页面坏了** —— CLI 完全不受影响，直接在终端做部署即可。
> 需要登录时把授权链接粘到浏览器打开（OAuth 授权页本身能正常加载）。

### 2.4 绑定域名

用 API 一次性绑两个（比控制台快，也不用等 SPA）：

```bash
TOKEN=$(grep -o 'oauth_token = "[^"]*"' \
  "$APPDATA/xdg.config/.wrangler/config/default.toml" | cut -d'"' -f2)
ACC=9dfd2a5ab648b9a7b57078df932aeb48
ZONE=93c8a3c9d6ebb85d82cc7b23c9e4d44a     # hacds.com

for host in hacds.com www.hacds.com; do
  curl -s -X PUT \
    -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
    "https://api.cloudflare.com/client/v4/accounts/$ACC/workers/domains" \
    -d "{\"zone_id\":\"$ZONE\",\"zone_name\":\"hacds.com\",\"hostname\":\"$host\",\"service\":\"hacds\",\"environment\":\"production\"}"
done
```

### 2.5 验证

```bash
# 本机 DNS 可能解析不到新域名，用 --resolve 指定 Cloudflare 边缘 IP
R="--resolve hacds.com:443:104.21.54.193"

curl -s $R https://hacds.com/ | grep -oE '<title>[^<]*</title>'
curl -s $R -o /dev/null -w "%{http_code}\n" https://hacds.com/app/
curl -s $R -o /dev/null -w "%{http_code}\n" https://hacds.com/docs/
curl -s $R -o /dev/null -w "%{http_code}\n" https://hacds.com/whitepaper/
curl -s $R https://hacds.com/assets/js/config.js | grep -E "apiBase|contract"

# 重定向（应 301）
curl -s --resolve hacds.com:80:104.21.54.193 -o /dev/null \
  -w "http → %{http_code} %{redirect_url}\n" http://hacds.com/
curl -s --resolve www.hacds.com:443:104.21.54.193 -o /dev/null \
  -w "www  → %{http_code} %{redirect_url}\n" https://www.hacds.com/

# 安全头（应能看到 nosniff）
curl -s $R -D - -o /dev/null https://hacds.com/ | grep -i x-content-type

# 关键：确认没把源码传上去（全部应为 404）
for p in /worker/index.js /README.md /wrangler.jsonc /.assetsignore /worker.js; do
  printf "%-20s " "$p"; curl -s $R -o /dev/null -w "%{http_code}\n" "https://hacds.com$p"
done
```

**2026-10-28 实测结果**：

| 项 | 结果 |
|---|---|
| `/` `/app/` `/docs/` `/whitepaper/` | 全 200 |
| `http://hacds.com/` | 301 → `https://hacds.com/` |
| `https://www.hacds.com/app/` | 301 → `https://hacds.com/app/` |
| 全部 21 个静态资源 | 200 |
| 白皮书三语 md + 中英 PDF | 200 |
| `/worker/index.js` 等 7 个敏感路径 | 全 404 |
| 安全头 | 5 个全部就位 |

## 4. 写操作需要额外部署构建服务

官网的 swap / 加池 / 撤池 / 借还都依赖 `POST /api/build`。

**不部署的后果**：官网只能**读**链上状态，所有写按钮点击后提示「交易构建服务尚未部署」。

### 4.1 服务器上部署

```bash
# 1) 编译引擎（只需一次）
cd /opt/hacash_fullnode
cargo build --release -p testkit --bin hacds_txbuild

# 2) 启动构建服务（默认只听 127.0.0.1:8125）
python3 /opt/hacds-build/hacds_build_server.py \
    --contract T1A8kaeWqK6wMUw5UMHCA6tMQ1iBdECyH \
    --txbuild /opt/hacash_fullnode/target/release/hacds_txbuild \
    --cors-origin https://hacds.com
```

详细说明见 [部署说明-构建服务.md](../hacds_exchange/indexer/部署说明-构建服务.md)。

### 4.2 暴露给 Worker

Worker 在 Cloudflare 公网，访问不到服务器的 `127.0.0.1`。两种做法：

| 做法 | 说明 |
|---|---|
| **A. nginx 反代 + TLS**（推荐） | `build.hacds.com` → `127.0.0.1:8125` |
| B. 服务听 `0.0.0.0` | 需自加防火墙 + IP 白名单，不推荐 |

nginx 片段：

```nginx
server {
    listen 443 ssl http2;
    server_name build.hacds.com;
    ssl_certificate     /etc/letsencrypt/live/build.hacds.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/build.hacds.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8125;
        proxy_set_header Host $host;
        proxy_set_header Origin $http_origin;
    }
}
```

然后在 Worker 里设 `BUILD_ORIGIN=https://build.hacds.com`。

### 4.3 验证

```bash
curl -s -X POST https://api.hacds.com/api/build \
  -H 'Content-Type: application/json' \
  -d '{"fn":"lp_harvest","params":"-","main":"<你的地址>","gasMax":99}'
# 期望：{"txbody":"03006a...","fee":"0.0002 HAC"}
```

## 6. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面能开但数据全「—」 | Worker 未配或后端不通 | 查 `curl https://api.hacds.com/vm/status` |
| 控制台报 CORS | `ALLOWED_ORIGINS` 不含当前域名 | Worker 变量里补上 |
| 控制台报混合内容 | `config.js` 的 `apiBase` 写成了 `http://` | 改成 `https://` |
| 写操作提示「构建服务尚未部署」 | `BUILD_ORIGIN` 未配 | 见 §4 |
| 官方域名打不开 | 自定义域未生效 | 等 DNS 传播，通常几分钟 |
| 白皮书 PDF 404 | 上传时漏了 `whitepaper/` 目录 | 重新上传完整目录 |
| **API 返回 `error code: 1003`** | **Cloudflare 连不上源站**（后端端口不通 / 防火墙 / 服务未起） | 在能访问的机器上 `curl http://43.251.101.101:8082/vm/status`；返回 000 就是后端问题，不是 Worker |
| **`/worker/index.js` 能访问** | 部署时把整个 `hacds.com/` 传上去了 | **紧急**：按 §2.2 用隔离目录重传，然后回滚上一版本 |
| **控制台白屏 / `page.goto` 超时** | `dash.cloudflare.com` 的 SPA 依赖 `*.workers.dev` 资源，国内被墙 | 别管它，用 wrangler CLI |
| **`npx wrangler login` 超时** | 授权后回调没打回 `localhost:8976` | 确认端口在监听（`netstat -ano \| grep 8976`），用最新一条链接重新授权，别复用旧链接（state 会不匹配） |
| 本机 `curl https://api.hacds.com` 返回 000 | 本地 DNS 解析不到新子域 | 加 `--resolve api.hacds.com:443:<CF边缘IP>` 绕过 |
| **页面开了但 HTTP 重定向不生效** | `wrangler.jsonc` 缺 `"run_worker_first": true` | 加上后重新部署（见 §2.2.1） |
| **`build.sh` 报 `Device or resource busy`** | 本地预览服务器（`python -m http.server`）还占着 `.build/public` | 先停掉那个进程再构建 |
| **本地改了文件、浏览器还是旧的** | 端口上有多个 `http.server` 残留进程 | `netstat -ano \| grep :8899` 找出全部 PID 逐个 kill，或换端口 |

## 7. 合约未部署时能上线吗

**可以。** 官网是纯静态展示 + 只读查询，合约未部署时：

| 功能 | 状态 |
|---|---|
| 首页、简介、文档、白皮书 | ✅ 正常 |
| 发行量验证器 | ✅ 正常（算的是全网 HACD，不依赖合约） |
| `/app/` 协议状态 | ⚠ 显示「未部署」或空值 |
| `/app/` 写操作 | ❌ 不可用（合约不存在） |

**建议**：先上线做公开审计展示，页面顶部横幅说明「#3000 待部署」，
合约部署后再更新横幅。

首页横幅在 `index.html` 的 `#banner` 元素，文案在 `assets/js/i18n.js`。
