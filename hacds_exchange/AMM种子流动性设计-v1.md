# AMM 种子流动性初步设计（决策点 4 · 供选择）

> 前提已锁定：HAC↔HACDS 用恒定乘积 AMM 定价；手续费 0.5% 收输出腿，80% 质押奖励池 / 20% 金库；奖励按费源币种发放。
> 本文只解决「池子怎么建、注多少、什么价、何时注」。

## 1. 注入机制（技术设计，无需选择）

**积分烧入式 add_liquidity（管理员专用外部函数）**：

1. 管理员先按普通用户流程转入 HAC 与 HACDS（Payable 钩子正常记积分）；
2. 同一笔交易内调用 `add_liquidity(hac积分数, hacds积分数)`：校验调用者积分足够 → 扣除 → 计入池计数器 `pool:hac`（zhu 计）与 `pool:dps`（HACDS 原子单位）；
3. **合约不设 remove_liquidity**：注入是单向的，池只能因用户兑换变小；项目方退出只能以用户身份按市价兑换——链上完全透明，无后门（防跑路信任设计）。

**性质**：
- 可多次注入（分批加厚）；按当前池比例注入 → 价格不变、只加深深度；偏离比例注入 → 价格随之移动（管理员定价权，链上可见）；
- 池空（k=0）时 HAC↔HACDS 兑换自动失败（除零保护）；HACD↔HACDS 评分兑换、赎回、领取奖励不受池影响；
- 池内 HACDS 腿为 HACD 存款人提供经 AMM 换 HAC 出金的通道，缓解「HACD 存款多、合约 HACDS 余额不足」的错配。

**上线顺序建议**：部署合约 → init_admin / set_oracle → 注入种子（add_liquidity）→ 开放存款与兑换。

## 2. 兑换路径（单笔 Type-3 三动作，原子）

以 HACDS→HAC 为例：

```
动作1 TransferAssetTo(合约, 数量)                 → Payable 记 HACDS 积分
动作2 ContractMainCall(swap_dps_to_hac, min_out)  → 按 x·y=k 报价，扣 0.5% 费，给调用者记 HAC 积分
动作3 TransferHacFrom(合约 → 我的地址, 数量)       → Permit 校验 HAC 积分足够，扣款放行
```

- 报价公式：`out = pool_hac × in / (pool_dps + in)`（整数下取整，256 位中间量，FitSH 已核实可实现）；
- `min_out` 由用户填写：报价低于它 → 整笔交易回滚（滑点保护）；
- HAC→HACDS 反向同理；HACD→HAC = 钻石转入（5 维评分记分）+ 同一 swap + HAC 转出；
- 兑换须本人发起（交易主地址 = 存款人）。

## 3. 待你选择的三个参数

### ① 规模 = 滑点深度

恒定乘积下，单笔兑换量占池子的比例约等于滑点：

| 池深度（HAC 腿） | 单笔 100 HAC | 单笔 1,000 HAC | 单笔 10,000 HAC |
|---|---|---|---|
| 1,000 HAC | ~11% | 不可用 | — |
| 10,000 HAC | ~1% | ~11% | — |
| 100,000 HAC | ~0.1% | ~1% | ~11% |

（HACDS 腿 = HAC 腿 ÷ 初始价 P，两边同时注入）

- **小池探路**：先 ~1,000 HAC 跑通，之后 add_liquidity 加厚；
- **标准池**：~10,000 HAC，单笔百级 HAC 滑点 ~1%；
- **深池**：~100,000 HAC，支撑单笔千级 HAC。

### ② 初始价格 = 注入比例

`P（1 HACDS 兑多少 HAC）= 注入 HAC 数 ÷ 注入 HACDS 数`。三种定法：

- **A 市场价锚定**：按二级市场当前 HACDS/HAC 参考价定比例——防止开放瞬间被套利搬走（需要你提供参考价）；
- **B 固定价**：你直接定一个整数价，简单但可能与市场偏离；
- **C 部署时再定**：机制留好，注入时你报两个数，比例即价格。

### ③ 注入节奏

- **一次性**：部署后、开放存款前一笔注入到位——开放即有稳定价格；
- **分批**：先注小池开放，观察兑换量与库存结构后加厚（加厚不改价）——占用资金少但早期滑点大。

## 4. 信任说明

- 种子流动性是项目方资金，注入后**无管理取出通道**（链上可验证）；
- 未来若要开放公众 LP（LP 份额 + LP 分成），走合约升级（ContractUpdate）实现，首发不含。

---

选定 ①②③ 后即进入正式 FitSH 合约编写（5 维评分 + 证书验证 + AMM + 质押奖励 + 金库清扫，单合约实现）。
