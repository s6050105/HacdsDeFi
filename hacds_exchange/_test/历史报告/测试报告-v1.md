## 3. 关键验证：`BYTE_TABLE` 替换

### 3.1 改动内容

```fitsh
// 原：buf_cut(BYTE_TABLE, count, 1)      ← 256 字节常量表，占 765 B
// 新：buf_cut("" ++ count, 15, 1)        ← 取 u128 拼接的最低字节
```

### 3.2 为什么有风险

这是**链上调用基因视图的 wire 格式**：

```
wire = count(u8) ‖ name × count
```

如果 count 字节算错，`hacd_visual_gene_batch` 会解析错误，导致 HACD 存入/赎回全部失败——而且是在链上不可修复的失败。

### 3.3 离线推理

u128 拼接为 16 字节大端，index 15 即最低字节：

| n | 16B 大端 | `buf_cut(x,15,1)` |
|---|---|---|
| 1 | `00…01` | `0x01` ✓ |
| 2 | `00…02` | `0x02` ✓ |
| 50 | `00…32` | `0x32` ✓ |
| 128 | `00…80` | `0x80` ✓ |
| 200 | `00…c8` | `0xc8` ✓ |
| 255 | `00…ff` | `0xff` ✓ |

### 3.4 链上实测

调用 `quote_score(WTYUIA)`：

```
输入：name=WTYUIA（hex 575459554941），vg=00×10，num=0
返回：ActCallError(95): diamond WTYUIA smelt not found
```

**这个返回证明了 wire 格式正确：**

- 若 count 字节错误 → 报「参数格式错误」或「名字列表非法」
- 若 wire 长度错误 → 报长度不匹配
- 实际报「钻石不存在」→ 说明节点**成功解析了 wire**，并去查了链上钻石

WTYUIA 在测试网上确实不存在（未挖出），所以报 not found 是正确行为。

**结论：`BYTE_TABLE` 替换有效。**

## 4. 遇到的问题与解决

| # | 问题 | 原因 | 解决 |
|---|---|---|---|
| 1 | 原合约 22,073 B 超限 | `max_tx_size = 16KB` 编译期常量 | 瘦身到 15,936 B |
| 2 | 分批部署失败 | 合约无 `Append` 钩子 | 方案排除，改瘦身 |
| 3 | 骨架部署报 `abstcall 65` | 钩子会调 external 函数 | 同上 |
| 4 | `fee_purity` 拒绝折扣部署 | 节点 `min_fee_purity` 门槛 | 测试网调低 |
| 5 | 高度 288 后难度抬升 | 非主网 ASERT 调整窗口 | 改 `difficulty_adjust_blocks` |
| 6 | 钻石挖不到 | 竞价难度 + 时间窗口太短 | 待重编节点后继续 |

## 5. 结论

### 可以确认的

1. **瘦身后的合约能正常部署**（15,936 B，实测成功）
2. **HAC 存提记账正确**（C1/C2 通过：`tot_staked` 与链上余额严格同步）
3. **13 个只读视图全部返回正确值**（G 阶段）
2. **`BYTE_TABLE` 替换正确**（wire 格式经链上验证）
3. **核心常量与初始化正确**（`hcut`/`lcut` = 1e12）
4. **对外接口未变**（前端无需改动）
5. **内核算法等价**（15/15 测试向量）

### 尚不能确认的

1. **HACD 存入/赎回的实际评分** —— 需要真实钻石
2. **200 颗批量存入** —— 核心新功能
3. **AMM 数学** —— 依赖 hacds 资产
4. **借贷与清算**
5. **全部攻击面**

### 风险提示

瘦身改动中，**风险最高的是 `BYTE_TABLE` 替换**，目前只验证了「wire 能被解析」，尚未验证「200 颗的真实评分计算」。B9 只能算部分通过。

**在 HACD 实测通过之前，不建议主网部署。**
