## 0. 直接回答：项目方收款地址能不能做？

**能。** 合约内置"金库"机制：

- 手续费在结算时按万分比切分，金库份额按资产分账累积在合约状态里；
- "清扫"交易把金库已累积的部分转到收款地址，钩子强制校验：收款方必须是金库地址、金额不得超过累积额，多转直接失败；
- 任何人都能发起清扫（合约转出不要求合约签名，授权完全由 Permit 钩子把关），资金只会流向金库地址，发起人碰不到钱；
- 收款地址本身可由管理员更换，也可升级为 M/N 多签（链上已有 `sigset_at_least` 签名集视图）。

详见第 5 节。

## 1. 设计约束（模型为什么长这样）

HVM 的底层规则决定了模型形态，以下均已从源码核实：

| 规则 | 对设计的影响 |
|---|---|
| 转入合约触发 Payable 钩子，转出触发 Permit 钩子；钩子内不能主动转账（TopOnly 策略） | 钩子只做记账与校验，"互换"由用户在同一笔交易里发起两个动作完成 |
| 同一笔 Type-3 交易的多个动作按顺序执行，钩子同步运行 | 动作1转入（钩子记账）→ 动作2转出（钩子按账本校验扣款）= **原子互换** |
| 8 个 Permit*/Payable* 钩子缺一即转账失败 | 全部注册；不支持的资产（SAT）返回非 0 拒绝 |
| 合约状态是 KV 存储，无前缀遍历 | 全局总量（总质押量等）用计数器维护，不扫描 |
| HACD 不可分割 | 手续费永远收在"可分割腿"（HAC 或 HACDS），绝不收钻石 |
| 合约地址不要求签名（req_sign 规则） | 转出交易任何人可提交，安全完全由钩子账本把关 |

## 2. 统一积分账本（核心模型）

三种资产入金折算成两种内部积分，积分同时是**交换媒介、赎回凭证、质押凭证**三位一体：

| 资产 | 入金所得 | 赎回方式 |
|---|---|---|
| HACD（钻石） | 按名称评分 ×10⁸ × 汇率 | 积分买回库存中**任意指定**钻石（手动选择） |
| HACDS（资产 #1028） | 1:1 | 1:1 |
| HAC | HAC 积分（以 zhu 计） | 费率模式 1:1；AMM 模式按池价 |

**评分规则（链上可完整复现的 nameliteral 维度）**：
six repeat 200 / Penta repeat 50 / Half repeat 20 / Two letters 10 / Quadro repeat 10 / AABCCD 10 / ABBCDD 10 / Symmetric letter 10 / Three letters 3 / Triple repeat 2 / Common 0，取最高分，×10⁸。

- **不做任何铭文判断**（已按你的指示取消）：转入的 HACD 直接按名称算分。
- 官方 hacds 服务是 5 维评分，其余 4 维（shapes/color/styles/numberliteral）依赖链下基因数据，VM 不可见。链上合约只算 nameliteral，与官方分数的系统性偏差用**全局汇率参数（cfg:rate，万分比，默认 10000）**补偿，管理员可定期校准。
- 汇率对称作用于进出两腿（入金折算与买回定价都用它），所以它是纯单位换算系数，不构成买卖价差；价差由手续费参数单独控制。

**"手动选择合约里的 HACD"**：钻石库存全局共享，任何积分持有者可在转出动作里指名购买库存中的具体钻石，钩子按 `sum(评分×汇率)` 扣积分。上一版草稿的"逐颗锁定 + 预授权赎回"模型升级为这个统一积分模型——更简单，且天然支持质押。

## 3. 互换模型（三者互换）

三对方向全部支持，**单笔 Type-3 交易原子完成**（动作1转入 + 动作2转出）：

| 交易对 | 定价 | 手续费收取腿 |
|---|---|---|
| HACD ↔ HACDS | 评分 × 汇率 | HACDS 腿 |
| HACDS ↔ HAC | 管理员费率 或 AMM 池（**待选**） | 输出资产 |
| HACD ↔ HAC | 上两条路径组合（一笔交易内完成） | HAC 腿 |

**流程示例（HACD → HACDS）**：
同一笔交易 = `TransferHacdTo(合约, 钻石名单)` + `TransferAssetFrom(合约, 我的地址, 1028, 数量)`。
动作1的 PayableHACD 钩子按评分给记积分；动作2的 PermitAsset 钩子校验积分足够 → 扣款 → 收手续费 → 放行。

**手续费规则**：始终收在可分割腿（HAC 或 HACDS）。默认费率 0.5%（万分之 50），管理员可在 0–3% 内调整。

## 4. 质押与利息（手续费 = DeFi 利息来源）

**积分即质押**：持有 HAC 积分或（HACD/HACDS）积分就是质押，无需单独操作。互换者只在同一笔交易内持有积分瞬间（微秒级暴露），长期持有者持续生息——两类用户自然区分。

- 每笔手续费按比例切分：**质押奖励池 / 金库**（默认 80/20，**待选**）。
- 奖励分配用"每单位累计值"（rpu）检查点法（Synthetix StakingRewards 模式）：
  - 收费时：`rpu += 费用 × 10¹² / 总质押量`（总质押量由计数器维护，防除零：总量为 0 时费用进待分配桶）；
  - 各账户余额变动时结算检查点，应得奖励 = 余额 × (rpu − 账户检查点)。
- 奖励币种（**待选**）：推荐**按费源币种发放**——HAC 手续费分给 HAC 积分持有者，HACDS 手续费分给（HACD+HACDS）积分持有者，合约零换汇风险。
- 领取奖励 = 普通转出动作，钩子把"应得奖励 + 可用积分"合并校验放行，无需单独交易。

## 5. 金库（项目方收款地址）

**机制**：
- 状态键 `cfg:treasury`（21 字节地址）+ `cfg:treasury_bps`（万分比分成）；
- 每笔手续费入账时同步给金库按资产记累积额（`feetreasury:hac` / `feetreasury:hacds`）；
- 清扫交易 = `TransferHacFrom / TransferAssetFrom(合约 → 金库地址)`，Permit 钩子校验：**收款方 == 金库地址 且 金额 ≤ 该资产金库累积额**；
- 任何人可发起清扫，资金只能进金库地址；手续费永不收 HACD，所以金库没有钻石、无分割问题。

**三种形态（待选）**：
- **A 可更新地址 + 比例（推荐首发）**：管理员可更换收款地址与分成比例，可加区块高度延迟锁（pending 值 + `block_height` 生效检查，两笔交易模式）；
- **B 多签金库 M/N**：清扫与改配置需 M 名管理员对交易签名，钩子内用 `sigset_at_least` 校验——适合后期治理升级；
- **C 部署时写死**：地址与比例固定在代码，最去信任但不可调整。

## 6. 管理与安全

- 管理员功能（external 函数，经 ContractMainCall 调用，`tx_main_addr() == admin` 校验）：
  `set_rate`（汇率，含上下限）、`set_fee`（费率 0–3%）、`set_split`（金库分成）、`set_treasury`、`set_paused`、`init_admin`、`register`（补登记裸转入的钻石）。
- 敏感变更可加时间锁：先提交 pending 值，`block_height ≥ 生效高度` 后第二笔交易确认。
- 暂停开关：暂停时 Payable 钩子拒绝新入金；**赎回与领取建议保持开放**（保护用户退出）。
- 合约代码可经 ContractUpdate 升级（管理员权限）——费率模式 → AMM 的演进路径依赖这一点。
- SAT 完全拒绝（PayableSAT / PermitSAT 返回非 0）。

## 8. 风险与限制（请重点审阅）

1. **评分偏差**：链上只算 nameliteral 维度，与官方 hacds 5 维分数存在系统性偏差，靠 cfg:rate 校准（管理员职责）；
2. **管理员权力集中**：汇率、费率、分成、金库地址、暂停均为管理员权限 → 建议多签 + 时间锁；
3. **AMM 模式需要种子流动性**；费率模式依赖管理员报价诚实；
4. **HACD 库存质量**：合约收到什么钻石完全由存款人决定，费率与汇率是对冲手段；
5. **成本**：ContractDeploy 需协议费（HAC），每笔 Type-3 交易需 gas（具体数值部署前按链上参数核算）。
