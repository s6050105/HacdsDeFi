# HACD / HACDS 抵押借贷 HAC 设计 v1（新增模块 · 供选择）

> 需求原话：抵押 HACD 或 HACDS 借 HAC，贷款只能贷取 50% 价值，超额抵押；利息超出 50% 价值时清算贷款，抵押物直接并入合约地址。
> 本模块与既有设计叠加：估值用 5 维评分（HACD）/ 1:1（HACDS）折 HACDS 积分，再经 AMM 池价折 HAC。

## 1. 账本模型

借贷不新增积分类型，复用两条状态键，按账户记账：

| 键 | 含义 |
|---|---|
| `loan:debt:<账户>` | 已借 HAC 本金（zhu 计）+ 已结转利息 |
| `loan:collateral_dps:<账户>` | 该账户锁定的抵押品价值（以 HACDS 积分计，×10⁸ 量纲） |

**抵押估值**：
- HACDS 抵押：1 HACDS = 1 HACDS 积分（1:1）；
- HACD 抵押：5 维评分 ×10⁸ = HACDS 积分价值（与存款/赎回同源同价）；
- 折 HAC 价值：`HAC价值 = collateral_dps × pool_hac / pool_dps`（AMM 即时池价，256 位中间量）。

**关键设计——抵押品即库存**：抵押的 HACD 直接进入合约钻石库存、HACDS 进入合约余额。**不锁定、不隔离**：抵押人仍可在同一笔交易里用积分买回自己的钻石（等价于还清贷款后赎回）。风险控制完全由「债务 ≤ 抵押价值 50%」这一条硬约束承担，简单且链上可验证。

## 2. 借款（单笔 Type-3 交易）

```
动作1 TransferHacdTo / TransferAssetTo(合约, 抵押品)      → Payable 记积分
动作2 ContractMainCall(loan_borrow, 借款额)               → 校验并记账
动作3 TransferHacFrom(合约 → 我的地址, 借款额)            → Permit 放行
```

`loan_borrow` 钩子逻辑：
1. `债务（含新借） ≤ 抵押HAC价值 × 50%`，违反 → 整笔回滚；
2. `loan:debt += 借款额`；HAC 积分同步记账（借款额从合约 HAC 余额出）；
3. 借款人 HAC 积分不增加——**借到的 HAC 是真币，直接转出**，债务记在贷款账本。

## 3. 利息（DeFi 收益第二来源）

- **利率**：`cfg:loan_rate`，万分比年化（按区块折算），默认 5%（500 bps），管理员可调 0–20%；
- **计息方式**：惰性结算——每次查询/还款/清算时 `debt = debt × (1 + rate × 经过区块/年区块数)`，256 位中间量，无浮点；
- **利息流向**：与互换手续费相同管道——80% 质押奖励池 / 20% 金库（复用第 6 节分配器，利息按 HAC 费源分给 HAC 积分持有者）；
- **结算时点**：还款、追加借款、清算时点结算入账。

## 4. 还款（单笔 Type-3 交易）

```
动作1 TransferHacTo(合约, 还款额)                        → Payable 记 HAC 积分
动作2 ContractMainCall(loan_repay, 还款额)               → 结算利息、扣减债务
```

- 还款额 ≥ 债务 → 债务清零，多余 HAC 记为账户 HAC 积分（可转出或留作积分）；
- 部分还款 → 先结利息（利息进分配器），余额扣本金；
- 还清后抵押品价值自动解锁（抵押积分恢复可用，可买回钻石或兑换）。

## 5. 清算（利息侵蚀超 50% 触发）

**触发条件**：`债务 > 抵押HAC价值 × 50%`（利息增长或池价下跌导致）。

**清算动作**：任何人可发起（去中心化清算，无需管理员）：

```
单笔交易：ContractMainCall(loan_liquidate, 借款人地址)
```

`loan_liquidate` 钩子逻辑：
1. 实时校验触发条件成立，不成立 → 回滚（防止恶意清算）；
2. `loan:debt` 清零；`loan:collateral_dps` 清零；
3. **抵押品价值直接并入合约**（HACD 留在库存、HACDS 留在余额，积分回收归合约）——按你的要求「抵押物直接并入合约地址」；
4. 清算人激励：`cfg:liquidate_bonus`，默认抵押价值的 2%，从被并合约的抵押价值中扣给清算人积分（鼓励及时清算，保护系统偿付能力）。

**清算后借款人状态**：债务归零、抵押归零——两清。借款人损失 = 抵押价值 − 债务 − 清算奖励（正常清算时点应尚有剩余，但池价暴跌时可能接近归零）。

## 6. 与既有模块的交互

| 模块 | 交互 |
|---|---|
| AMM 池 | 估值折 HAC 用池价；借款 HAC 来自合约 HAC 余额（与池共用一个余额，池计数器只是记账） |
| 质押奖励 | 利息进 80/20 分配器，HAC 利息分给 HAC 积分持有者 |
| 金库 | 利息的 20% 进金库累积额 |
| 钻石库存 | 抵押的 HACD 直接入库，可被他人买回（买回者付积分，抵押人债务不受影响——价值守恒：抵押人锁定积分减少 = 他人库存购买增加） |

**一个必须说明的边界情况**：抵押钻石被他人买走后，该账户 `loan:collateral_dps` 不变（价值仍记在账上），但实物钻石已易主。这在「抵押品即库存」模型下是自洽的——抵押锁定的是**价值额度**而非实物。若你希望抵押钻石**锁定不可购买**（需额外的锁定标记 + 买回校验），见第 8 节选项 B。

## 7. 安全边界

- **合约 HAC 偿付能力**：借款总额受两个天然上限约束——① 每笔 ≤ 抵押价值 50%；② 合约 HAC 余额（含 AMM 池）。合约 HAC 不足时借款动作自动失败；
- **预言机风险**：HACD 估值依赖基因证书（同存款），预言机作恶影响估值——缓解同第 9 节；
- **清算竞争**：清算先到先得，任何人可发起，无许可；
- **暂停**：暂停时禁止新借款，还款与清算保持开放。
