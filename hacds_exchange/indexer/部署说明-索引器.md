# HACDS 索引器 · 服务器部署说明

> 目标服务器：`43.251.101.101`（已运行 Hacash 全节点 + 预言机）
> 索引器脚本：`hacds_indexer.py`（单文件，零第三方依赖，Python 3）

## 0. 结论先行：索引器是**只读消费者**

- 它只做一件事：**GET 全节点 RPC**，遍历区块把「调用过借贷函数的地址」收集成台账。
- **从不提交交易**（代码中无任何 `/submit` 调用）、**不需要私钥**、**不需要余额 / gas**。
- 它与预言机（`hacds_oracle.py`，8123）**互不依赖**，可各自独立启停。

```
全节点 :8082 ──GET──► hacds_indexer.py :8124 ──GET /watchlist──► 钱包（PC / Android）
```

## 1. 为什么需要它（不能靠合约枚举）

合约**无法枚举借款人** —— 三个已核实的事实：

| 尝试 | 结果 |
|---|---|
| 合约有没有借款人列表 / 注册表？ | ❌ 借款账目按 `loan:debt:<addr>` **拼键**存储 |
| 合约会不会写日志？ | ❌ 无 `log_push` |
| 节点能否按前缀枚举合约 KV？ | ❌ `debug contract/storage` 只支持**精确 key** |

所以只能**遍历区块**，从历史交易里把借款人挖出来。

## 2. 原理（已验证的链上原语）

```
1) GET /query/block/intro?height=N&tx_hash_list=true
      → 该块的交易哈希列表
2) GET /query/transaction?hash=H&action=true
      → 结构化动作 [{kind, ...}]
3) 合约调用 kind=44，其 codes 内含 selector = sha3_256(函数名)[0:4]
      → 用借贷函数 selector 白名单过滤；命中则 tx.main_address = 借款人
```

字节码形态为 `09 14 01 <sig4> ee`（由 `hacds_txbuild` 实际生成的交易验证 3/3）。

### ⚠️ 关键语义：`loan_status` 的返回值**不是**健康度百分比

| 返回值 | 含义 |
|---|---|
| `0` | 无借贷、无抵押 |
| `999` | 有抵押但**无债务**（安全） |
| 其它 | `coll_hac × 100 / debt`（抵押率 × 100） |

清算门槛来自合约 `loan_liquidate`：要求 `debt > coll / COLL_RATIO(2)` 才放行，
即 `coll_hac / debt < 2` ⟺ **`health < 200`**。

> **可清算 ⟺ `debt > 0 && 0 < health < 200`**

（初版曾误写成 `health < 10000`，把「无借贷」标成「可清算」；已修正并有自检覆盖。）

## 3. 服务器前置

- Python 3（**仅标准库**：hashlib / hmac / json / struct / urllib / http.server / threading）
- 可访问的全节点 RPC

> **扫描吞吐（实测）**：串行约 2.6 块/秒（每块 = 1 次 block/intro + 每个 tx 1 次查询），
> 并发 `--workers 4` 约 **6.6 块/秒**。首次回溯 500 块 ≈ **75 秒**；之后每轮只扫新增块（60 秒一轮 ≈ 2~3 块），几乎无感。
>
> ⚠️ 注意：**必须确认节点 API 端口**。本机开发环境是 `8082`，
> 脚本默认却是 `127.0.0.1:8082`；若服务器不同，启动时显式传 `--node`。

## 4. 放置与启动

```bash
sudo mkdir -p /opt/hacds-indexer
# 上传脚本（从开发机 scp，或直接粘贴）
sudo cp hacds_indexer.py /opt/hacds-indexer/
sudo chmod 755 /opt/hacds-indexer/hacds_indexer.py
cd /opt/hacds-indexer

# 自检（离线，含 sha3 官方测试向量 + selector + 清算判定）
python3 hacds_indexer.py selftest          # 应输出 SELFTEST PASSED

# 先跑一次扫描看效果（前台，Ctrl-C 退出）
python3 hacds_indexer.py scan --node http://127.0.0.1:8082

# 常驻服务
python3 hacds_indexer.py serve --node http://127.0.0.1:8082 --port 8124 --interval 60 --workers 4
```

## 5. 参数说明

| 参数 | 默认 | 说明 |
|---|---|---|
| `--node` | `http://127.0.0.1:8082` | 全节点 RPC |
| `--contract` | `VKNwXFFMCEn9XfMrhyHhd5rHqBnEyM3m1` | 合约地址 |
| `--state` | `./watch.json` | 台账落盘路径 |
| `--window` | `500` | **首次**回溯块数。⚠️ 2000 块 ≈ 4000 次 HTTP，很慢；增量同步后每轮只扫新增块 |
| `--port` | `8124` | HTTP 服务端口 |
| `--interval` | `60` | serve 模式轮询秒数 |
| `--workers` | `4` | 并发扫块线程数。**实测**：串行 ~2.6 块/秒，并发 4 → **~6.6 块/秒**（100 块 38s→15s） |

## 6. HTTP API

| 路径 | 说明 |
|---|---|
| **`GET /watchlist`** | ★ **钱包唯一需要的接口**：概况 + 台账快照（含实时健康度） |
| `GET /snapshot` | 仅台账快照 |
| `GET /health` | 存活探测（返回当前高度、台账地址数） |
| `GET /sync` | 立即同步一次 |
| `GET /watch/add?address=…&note=…` | 手工加观察地址 |
| `GET /watch/remove?address=…` | 移除观察地址 |

`/watchlist` 返回示例：

```json
{
  "ret": 0, "head": 792523, "watched": 3, "withDebt": 1, "liquidatable": 1,
  "snapshot": [
    { "address": "1...", "health": 150, "healthPct": 1.5, "debt": 1000,
      "coll": 300000000, "liquidatable": true, "noLoan": false,
      "first": 792100, "last": 792500, "calls": 4, "fns": {"loan_borrow": 1} }
  ]
}
```

## 7. 以 systemd 常驻（可选）

```bash
sudo cp hacds_indexer.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now hacds-indexer
sudo systemctl status hacds-indexer
tail -f /var/log/hacds-indexer.log
```

## 8. 钱包端配置

在钱包顶部网络栏的「**索引器**」输入框填 `http://43.251.101.101:8124`（或留空）。

- **填了** → 清算页只调一次 `/watchlist`，**不本地扫链**（推荐；手机端尤其重要）
- **留空 / 服务不可达** → 自动**回退本地扫块**（慢，但可用）

清算页会显示索引器状态：`索引器在线，高度 N，台账 M` 或 `索引器未连接（将本地扫块，较慢）`。

## 9. 安全说明

- 索引器**无写权限**、无密钥、不含任何签名逻辑。
- `Access-Control-Allow-Origin: *`（只读接口，便于手机/浏览器直连）；若部署在公网，
  建议在反向代理层加**限流**（接口本身很轻，但 `/sync` 会打节点）。
- 台账文件 `watch.json` 由**服务端**持有；钱包的增删会写回服务端（若已配置索引器）。
