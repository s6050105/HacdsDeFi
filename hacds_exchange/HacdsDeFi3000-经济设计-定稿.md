## 1. 一句话看懂

> **拿钻石换稳定份额，拿 HAC 赚利息，拿流动性赚手续费。**
> **风险不会凭空消失，它被明确分配给了承担它、并因此获得收益的人。**

具体来说：

- AMM 池里的 HAC，**只有 30% 能借出去**，另外 70% 永远留着让人随时交易和撤退。
- 借款总利用率最高 **50%**，任何时候都至少有一半现金在池子里。
- 贷款利息 **80% 归存钱的人**，20% 留作坏账储备。
- 会有坏账吗？会有。极端情况下所有人按比例分担，**没有谁能例外**。

## 4. 存 HACD 换 hacds

### 怎么运作

你存入 1 颗 HACD 钻石，合约按这颗钻石的**品质打分**，给你同等分值的 hacds。
**不打折，1 分就是 1 分。**

hacds 是完全按钻石置换发行的，**总量固定，永远不可能超发**。

### 到底能拿到多少

**1 分 = 100,000,000 个 hacds**（一亿个）。

| 钻石评分 | 拿到的 hacds |
|---:|---:|
| 1 分 | 1 亿 |
| 3.55 分（全网平均） | 3.55 亿 |
| 10 分 | 10 亿 |

这里的「分」是合约对钻石的五维打分（形状/样式/颜色/命名/编号），
全网钻石平均约 **3.55 分**。

> **hacds 的数量就是个数，没有小数。** 1 个就是 1 个，不存在「1.5 个」。
> 总量固定为 5,963,298,700,000,000 个，**只减不增**，不存在增发函数。

### 一次只能存一颗

技术限制，一次交易存一颗。多颗就多笔。

### 赎回来

拿 hacds 换回钻石，付 **0.5%** 手续费。

**但如果你的钻石品质高于池子平均水平，要额外付费。**

### 为什么高分钻石要多付钱

池子里的钻石是混在一起的。如果赎回免费，聪明人会：
存 100 颗普通钻石进去 → 等别人也存 → 把最好的几颗挑走。

结果是留下来的人拿到的都是差钻石。这个额外费用就是**针对这种挑拣行为的税**：

> 高于平均分越多，费率越高，**最高 30%**。

普通和低分钻石**不额外收费**，正常赎回。

### 一个具体例子

池子平均分 100，你想赎回的钻石值 150 分：

```
超出比例 = (150 - 100) / 100 = 50%
额外费率 = min(30%, 50%) = 30%
总手续费 = 0.5% + 30% = 30.5%
```

如果你赎回的钻石值 105 分：

```
超出比例 = 5%
额外费率 = 5%
总手续费 = 0.5% + 5% = 5.5%
```

### 多付的这些钱去了哪

**基础 0.5% 和挑钻石溢价，在合约里是同一笔费用，走同一条分配路径：**

```
赎回手续费 100%
  ├─ 80% → 流动性提供者（按份额比例分）
  └─ 20% → 金库
```

池子里没有 LP 时，那 80% 也一并进金库。

举个极端例子——赎回一颗 1000 分的钻石，赶上 30% 满额溢价：

| 项目        | 数量       |
| --------- | --------:|
| 本金（销毁的份额） | 1000     |
| 基础费 0.5%  | 5        |
| 挑钻石溢价 30% | 300      |
| **总共扣走**  | **1305** |

这 1305 的去向：

- **1000** 是真的销毁——池子里少了这颗钻石的账面份额
- **305** 是手续费 → **244 给 LP，61 进金库**

验算：`1305 − 244 − 61 = 1000`，正好等于被赎回钻石的份额。
**没有凭空产生任何 hacds。**

### 为什么溢价给 LP 而不是金库

因为挑钻石损害的是**留在池子里的人**——好钻石被挑走后，剩下的人手里的份额
对应的是一个变差的钻石池。

谁受损，谁拿补偿。

## 5. 存 HAC 赚利息

### 收益来源

别人借 HAC 付的利息，**80% 分给存钱的人**。

### 利息怎么算

利率是浮动的，看池子里**总共有多少钱**被借走了：

- 借得少 → 利率低（最低 2%）
- 借得多 → 利率高（最高 46%）

这里的「利用率」= 总借款 ÷ 所有可出借的资金（存款 + AMM 里可出借的那 30%）。

⚠️ 注意：**借满 50% 时的利率是 46%**。利用率上限和利率上限是同一个数字，
不是「随便借都只有 2%」。

### 你承担多少信用风险

这取决于你是哪种存款人：

| 你的钱在哪              | 承担多少信用风险                   |
| ------------------ | -------------------------- |
| 直接存 HAC（`bal:hac`） | **全部**。坏账瀑布第 5 步就是扣所有人     |
| 放在 AMM 池子里做 LP     | 只有**可出借的那 30%**，剩下 70% 不承担 |

AMM 池里有大量 HAC，但**只有 30% 能借出去**。所以 LP 只按 30% 那份赚利息，
也只承担 30% 的坏账风险。

**直接存 HAC 的人赚全部利息的 80%，也承担最后的损失。**
想避开信用风险，就去提供流动性；想拿全额利息，就接受社会化风险。

### 随时能取吗

不一定。如果借出去的钱太多、现金不够，取款会被拒绝。

**这是故意的。** 协议宁可让你等（等借款还回来或有人来存款），
也不写一个复杂的排队系统——**合约不可升级，排队逻辑写错就是资金死锁**。

好在有两层保护，这种情况很少发生：

- 借款总量上限 50% → 永远至少一半现金
- AMM 70% 预留 → 交易和撤退始终有缓冲

## 6. 借 HAC

### 怎么借

1. 先存入 HACD 拿到 hacds
2. 用 hacds 当抵押品
3. 最多借出抵押价值的一半

### 你的健康度

系统用一个数字表示你的仓位安全程度：

```
健康度 = 10000  → 正好在清算线上，危险
健康度 > 10000  → 安全
健康度 < 10000  → 可以被清算
```

界面显示的健康度和链上真正清算用的是**同一个价格**，不会出现「界面看着安全、实际已被清算」。

### 注意：健康度用保守价格算

清算时的抵押估值用的是 `min(市场现价, 平滑参考价)`。

也就是说，价格暴涨时按不上的那部分不算数，**只认低的那一个**。
这是在保护协议，但对借款人略保守。

## 7. 给交易池提供流动性

### 收益

| 来源                 | 比例      |
| ------------------ | ------- |
| 交易手续费              | **80%** |
| 借贷利息（仅可出借的 30% 部分） | 按比例分配   |
| 赎回手续费              | **80%** |

### 风险

1. **无常损失**：HAC 和 hacds 的相对价格变化会让你退出时拿到的组合价值低于单纯持有。
   这是所有 AMM 的固有特性，不是这个协议特有的。
2. **信用风险**：池子里有 30% 的 HAC 被借出去。如果大面积坏账，这部分会受损。
   **最多损失这 30%。**

> ⚠️ 这是**明确的取舍**。如果你想完全避开信用风险，就不要提供流动性。
> 协议不会隐瞒这一点。

## 8. 清算：什么时候你的抵押会被卖掉

### 触发条件

```
抵押价值 < 债务 × 1.6
```

也就是钻石价格从你借款时算起**跌了 20%**（如果你借满了）。

### 普通清算（抵押率在 105%–160% 之间）

- 一次最多清算你 **50%** 的债务
- 清算人替你还钱，拿走「还款额 + 5%」价值的抵押品
- 你保留剩下的抵押品和债务

**为什么要限制 50%？** 给借款人留出补救的机会，而不是一次清光。

> 注意：「能从 160% 跌到这个区间」说明价格已经跌透了。这个区间的意思是
> **已经跌破 160% 但还没跌破 105%**，此时清算只砍一半，不会清光。

### 深度清算（抵押率跌破 105%，已经很危险）

- 可以**一次清算全部债务**
- 清算人享受 **3% 折扣**
- 协议承担剩下的损失

### 关键：清算奖励按还款额算，不按债务比例

这一点很容易误解。举例：

```
你的债务 100，抵押价值 159（抵押率 159%，刚跌破 160% 线）
清算人还了 50
清算人拿走的抵押 = 50 × 105% = 52（52.5 向下取整）
占你总抵押的 32.7%
你保留 67.3%
```

如果是错误的「按比例分配」，清算人会拿走 50/100 × 159 = 79.5 的抵押价值，
超过一半。**实际不会这样**——清算人只能赚他垫付金额的 5%，赚不到抵押品的比例。

### ⚠️ 没有宽限期

**合约里没有任何等待时间。** 一旦抵押率跌破 160%，任何人都可以立刻清算你，
不需要你「先收到通知」，也不存在「给你 N 个小时补仓」的机制。

（讨论过「借款宽限期」，但 **v1 没有采用**——理由见表末「本文档不包含什么」。）

### 但清算不会一次清光你

限制单笔 50% 带来的效果比想象中强。因为**奖励按还款额算**，
清算掉一半债务只会拿走约三分之一的抵押：

|                  | 债务  | 抵押  | 抵押率           |
| ---------------- | ---:| ---:| -------------:|
| 清算前              | 100 | 159 | **159%** ← 危险 |
| 清算人还 50，拿走 52 抵押 | 50  | 107 | **214%** ← 安全 |

**债务减了 50%，抵押只减了 33%。**

清算一结束，抵押率从 159% 跳到 214%，**立刻脱离危险区**。
下一次清算至少要等钻石**再跌 25%**（107 → 80 才触线）。

继续往下也是这样：

```
第 1 次后：抵押率 214%（安全）
第 2 次需再跌 25% 才触发，清完变 321%
第 3 次需再跌更多……
```

每次砍一半债务，抵押率反而越清越高。
所以在**同一个价位上**，清算人不可能连着清你两次——清完一次就脱离危险区了。

**但这不是「永久安全」。** 如果价格继续下跌，你会被再次清算。
机制阻止的是「同一时刻连续爆仓」，不是「价格持续下跌时的反复清算」。

### 你实际拥有的时间是「市场的」，不是「系统的」

| 你的抵押率     | 状态       | 会发生什么                                  |
| --------- | -------- | -------------------------------------- |
| > 160%    | 安全       | 什么都不会发生                                |
| 105%–160% | **可清算区** | 随时可被清算，**零等待**。单次只砍一半债务，之后抵押率会升到 200%+ |
| < 105%    | 深水区      | **一次清完全部债务**，没有第二次机会                   |

所以要分清两件事：

- **单次清算**不会清光你——砍掉一半债务，抵押率反而升到 200% 以上
- **但如果价格持续下跌**，你会被反复清算，每次砍一半，直到某一刻跌破 105% 被一次清完

真正决定你有多少反应时间的，是**价格下跌的速度**。
**市场决定，协议不承诺任何时长。**

### 借款人该怎么做

1. **别借满。** 借到 50% 上限时一点缓冲都没有；借 30%–40% 会从容很多。
2. **盯 `loan_health` 视图。** 它用 `min(现货价, 参考价)` 计算，和链上清算**完全同一口径**，
   不会出现「界面显示安全、实际已被清算」。
3. **150% 附近就开始补仓**，不要等到 160%。
4. **知道自己在赌什么**：没有宽限期，价格到了就是到了。

## 9. 极端情况：坏账怎么处理

### 坏账从哪来

钻石价格暴跌，抵押品价值低于债务，清算也填不上窟窿。

### 处理顺序（一步一步，按这个次序）

```
1. 储备金        ← 平时攒下的 20% 利息，先顶上
2. 金库手续费    ← 协议累计的收入
3. LP 奖励池     ← 未领取的 LP 收益
4. LP 的本金     ← 最多损失可出借的那 30%
5. 所有存款人    ← 按比例，人人有份
6. 记成赤字      ← 等未来收入慢慢补
```

### 第 5 步意味着什么

如果损失大到前四步都填不上，**所有存 HAC 的人余额会按同一比例缩水**。

不是「某些人倒霉」，是**所有人一起**。

### 这个比例叫 hcut

系统不逐个地址扣钱，而是维护一个全局系数 `hcut`：

```
你的实际余额 = 账面余额 × hcut
```

hcut 初始是 1（100%）。发生社会化损失时，它会**永久降低一次**。

**hcut 只降不升。** 今天缩水的部分，不会因为未来协议赚钱而恢复。

这是一次性的、不可逆的、透明的损失。

### 为什么这样设计

其他方案都有更严重的问题：

- **不社会化** → 坏账一直挂着，赤字越滚越大，最后整个协议资不抵债
- **逐个地址扣** → 合约无法枚举所有地址，技术上做不到
- **只有 LP 承担** → LP 会被吓跑，池子干涸

公开、按比例、一次到位——是唯一能持续运转的选择。

## 10. 价格从哪来

### 不用外部预言机

价格直接从 AMM 池子里读：池子有多少 HAC、多少 hacds，两者相除就是价格。

**所以：没有第三方喂价，也没有第三方可以伪造价格。**

### 但也不能直接用现价

如果有人在一笔交易里把池子价格砸下去再触发清算，就能偷走抵押品。

所以协议用一个**平滑参考价（EMA）**：

```
新参考价 = 老参考价 × 大部分 + 当前现价 × 小部分
```

单笔交易最多让参考价移动 **10%**，而且正常情况下每次只能动 1/300。

**砸盘操纵变得非常昂贵且低效。**

### 熔断保护

如果现价和参考价偏离超过 **20%**，协议会：

- ✅ **暂停新增借款**
- ✅ 继续更新参考价
- ✅ 清算照常进行
- ✅ 还款、补抵押照常进行

只掐住「借钱」这一个动作。这是为了防止有人在价格异常时借走钱。

## 11. 费用都去了哪

```
交易手续费 100%
  ├─ 80% → 流动性提供者
  └─ 20% → 储备金

贷款利息 100%
  ├─ 80% → HAC 存款人
  └─ 20% → 储备金

赎回手续费 100%
  ├─ 80% → 流动性提供者
  └─ 20% → 金库

清算奖励 100%
  ├─ 4% → 清算人（净赚）
  └─ 1% → 储备金
```

注意：上面的百分比是**收入内部的分配比例**，每项加起来各是 100%（赎回和交易费的
HAC/hacds 两条腿都按这个比例分）。

### 储备金是干什么的

**第一道防线。** 出坏账时先从这里扣，扣不到才会轮到存款人。

储备金有上限：**不超过总存款的 3%**。攒够了就不再攒，多出来的进金库。

#### 一个细节：清算费不经过这个上限

利息和交易费的 20% 走的是储备分配函数（先补赤字、再补到 3% 目标、余下进金库）。

**但清算的那 1% 是直接写进储备的**，不走这个函数，所以：

- 它不受 3% 上限约束
- 也不会先去填赤字

实际影响很小——清算费量级远小于利息，而且**储备多了只会更安全**。
唯一的可见结果是：连环爆仓时储备会比设计值厚一些，同时利息和交易费会更多地流进金库。

### 金库

金库是协议的收入账户，地址是一个冷钱包。

任何人都可以触发「清扫」，把累积的手续费转进金库。
**但只有金库私钥持有人才能真正动用这笔钱。**

## 12. 你需要知道的四个风险

### 风险一：钻石价格下跌会被清算

钻石跌 20%（满借时）就会触发清算。

**而且没有宽限期** —— 跌到线就随时可被清算，不会提前通知你。

**应对**：

- 别借满，多留缓冲
- 盯健康度，**150% 附近就补仓**，不要等 160%
- 理解清算不是一次性的：价格继续跌会被反复清算

### 风险二：存款人的余额可能按比例缩水

极端坏账会触发社会化，所有存 HAC 的人一起承担。

**应对**：理解这是协议的最后防线，不是bug。储备金和 LP 缓冲会吸收大部分损失。

### 风险三：取款可能暂时被拒

借出去太多、现金不够时，取款会失败。

**应对**：别把所有钱都拿去存。协议不承诺随时可取。

### 风险四：合约不可升级

代码写死在链上，**发现 bug 也改不了**。

**应对**：这就是为什么参数设计得保守（20% 缓冲、50% 上限、两层现金保护）。
也是一个理由：**别把全部身家放进来**。

## 13. 常见问题

**Q：hacds 会增发吗？**
不会。按钻石等值发行，总量固定，没有增发函数。

**Q：有没有管理员能拿走我的钱？**
没有管理员。合约里没有任何人可以暂停、修改参数、或者转走用户资产。

**Q：APY 是多少？**
浮动的。存款收益取决于借出去多少，借款成本 2%–46% 之间浮动。界面会显示实时值。

**Q：钻石跌了怎么办？**
跌到清算线以下，清算人会替你还债并拿走部分抵押。剩下的还是你的。

**没有宽限期**——跌到 160% 就随时可被清算，不会提前通知。
单次清算只砍一半债务，但价格继续跌会被反复清算；跌破 105% 会被一次清完。

跌之前补抵押或者还一部分，就不会被清算。

**Q：为什么赎回高分钻石要多付钱？**
防止有人把池子里的好钻石挑走。这是对「挑拣行为」的税，不是对你个人的惩罚。

**Q：协议赚的钱去哪了？**
金库。金库地址是公开的，任何人都能查余额。

**Q：会不会跑路？**
合约里没有提款函数，没有管理员权限，代码公开可审计。
但**金库私钥是单点**——这是唯一需要信任项目方的地方。

**Q：钻石价格数据从哪来？**
不用外部数据源。直接读 AMM 池子的余额比例，没有人能伪造。

## 附：本文档不包含什么

以下是讨论过但**没有采用**的方案，这里列出来是为了避免误解：

| 没做的        | 原因                                                                                          |
| ---------- | ------------------------------------------------------------------------------------------- |
| 治理代币       | 不需要。参数写死，靠自动机制调节                                                                            |
| 管理员 / 暂停开关 | 不需要。没有管理员就没有作恶空间                                                                            |
| mint 折扣    | 不必要。按钻石等值发行，不存在超发风险                                                                         |
| 提现排队队列     | 太危险。合约不可升级，排队逻辑写错就是资金死锁                                                                     |
| 借款宽限期      | **借款人没有等待期**。理由：清算按还款额计奖，单次只砍一半债务却能立刻拉高抵押率，实际很少需要连续清算；加宽限期要多一个状态键和一条失败路径，还会延迟坏账处置、放大损失。见 §8 |
| 荷兰式拍卖清算    | 会流拍。固定折扣可预测、实现简单                                                                            |
| 稳定池        | 启动不起来。需要预先锁定大笔资金，协议还没这个规模                                                                   |
| 外部预言机      | 不需要。直接读池子价格，没人能伪造                                                                           |
| 多签金库       | 已决定用单一冷钱包，接受这个风险                                                                            |

以上每一项都是**权衡后的选择**，不是遗漏。
