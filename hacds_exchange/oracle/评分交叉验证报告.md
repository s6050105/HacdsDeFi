## 验证方法

### 1. 官方 Java 独立编译运行（最强基准）

官方 `AnalyseDiamond.java` 依赖 Spring/lombok/fastjson，无法直接运行。验证时将其算法条件
**逐行拷贝**成独立 Java 程序（`OfficialCheck.java`，仅剥离依赖，规则链、字符串常量、
尾随空格、双 map 结构全部原样保留），用本机 JDK 17 编译运行，作为「官方语义」的可执行基准。

对齐的关键官方语义：
- `map`（完整 metric_en 键，含 `"Right mix pure "` / `"Sum seven color "` 尾随空格）供
  `getMaxScoreFeature` 查分；`cleanMap`（`split("\\|")[0]` 短名键）供 `setDiamondScore` 查分；
- `getMaxScoreFeature` 降序稳定排序 → **等分并列取 rule.txt 中先出现者**；
- `number symmetry` / `serialRepeat` 在官方源码中已被注释，不参与计分；
- Common 形状走 styles、非 Common 走 color 的互斥分支。

### 2. 主网真实钻石批量对比

从 hacd.fun 的全节点代理 API（`/api/hacash/diamond/views`）随机采样 **390 颗主网真实钻石**
（name + life_gene + number），三方对比：

| 对比 | 结果 |
|---|---|
| 预言机 Python vs 官方 Java：总分 | **390/390 一致（100%）** |
| 预言机 Python vs 官方 Java：五维标签逐项 | **1950/1950 一致（100%）** |
| visual_gene 派生（Python vs hacd.fun `eo`） | **390/390 一致（100%）** |
| hacd.fun 前端 vs 官方 Java：总分 | 387/390 一致（3 颗分差，见下） |

### 3. 随机 fuzz

- 10,000 颗随机构造钻石（随机名字/编号/visual_gene）：Python vs Java 总分 **0 分差**；
- 5,000 颗维度标签逐项 fuzz：修正前发现 2 处等分并列标签差异（总分相同），修正后 **0 差异**；
- 修正后同种子复跑 + 新种子 10,000 颗：**0 差异**。

## 发现并修正的问题

**等分并列的取值顺序**（fuzz 发现，总分不受影响、标签受影响）：

- `77777` 同时命中 Tail five(50) 与 Repetition(50)——官方按 rule.txt 顺序取 **Tail five**，
  修正前我的实现取了 Repetition；
- `HMMMMH` 同时命中 Two letters(10) 与 Quadro repeat(10)——官方取 **Two letters**。

修正：`get_nameliteral` / `get_numberliteral` 的条件链顺序改为 rule.txt 中对应 typeEn 的
出现顺序（已固化进 selftest 断言）。

## hacd.fun 与官方 Java 的实现差异（3 颗分差全部归因）

hacd.fun 前端对官方算法做了三处自行修改，导致 3/390 颗分差：

| # | 差异 | 官方 Java | hacd.fun 前端 | 受影响样本 |
|---|---|---|---|---|
| 1 | **Right mix pure 条件不同** | `13==14 && 15==16 && 15!=13`（前两位同 + 后两位同） | 后三位相同且 ≠ 首位 | NITVSB（官方 3 分 vs hacd.fun 20 分） |
| 2 | **Number Symmetry 启用** | 源码已注释，回文编号 0 分 | 启用，回文编号 10 分 | IIUMWH（0 vs 10）、NUNUMN（23 vs 33） |
| 3 | Symmetry→"Color Symmetry"、Half repeat→"ABCABC" 改名 | 原名 | 改名（条件相同，分值相同） | 无分差 |

另有两处等价性确认（非差异）：
- hacd.fun 的 `eo` 基因派生输出 20 hex，与官方 `calculate_diamond_visual_gene` 在
  `ei` 所用全部切片（形状 [0:2]、样式 [2:18]、颜色 [2:19]）上**逐字节等价**（390/390）；
- `analyseColorType`（Set 判定）与官方 `darkOrLight` 功能等价。

**结论：以官方 Java 为准的实现是本预言机；hacd.fun 的三处偏差不采纳**（官方服务才是
HACDS 发行定价的同源基准）。若未来 hacd.fun 修正其前端，两边分数将完全一致。

## 结论

预言机评分模块与官方 `AnalyseDiamond.java` + `rule.txt` **逐字节对齐**：
390 颗主网真实钻石 + 15,000 颗 fuzz，总分与五维标签 100% 一致；
与 hacd.fun 的 3 颗分差全部归因于 hacd.fun 自行修改的规则，官方语义无误。

selftest（离线，21 项断言）已包含关键对齐用例：
`python hacds_oracle.py selftest`


## 补充：NITVSB 争议与 Diamond_Analyzer v0.1.1 对比（2026-10-19 第二轮）

### NITVSB（#19474，visual_gene = d9f418dc195372199970）四方评分

styles 板（vg[2:18]）第 13–16 位 = `1,9,9,9`：

| 实现 | Right mix pure 条件 | 命中 | styles 结果 | 总分 |
|---|---|---|---|---|
| **官方 hacds Java**（AnalyseDiamond.java） | `13==14 && 15==16 && 15!=13` | 否（'1'≠'9'） | Edge color（15==16 且 13≠14） | **3** |
| hacd.fun 前端（ei 类） | `14==15==16 && 14!=13` | 是（后三位 '999'） | Right mix pure | 20 |
| Diamond_Analyzer v0.1.1 | `fourteen==sixteen==fifteen && fourteen!=thirteen` | 是（同 hacd.fun） | Right mix pure | 20 |
| 本预言机 | 与官方 Java 逐条一致 | 否 | Edge color | **3** |

「右三混合」的字面语义（底部 4 条颜色条的第 1、3、4 条相同）对应 `14==15==16 && 14!=13`
——hacd.fun 与 Diamond_Analyzer 的实现符合该语义；但**官方 hacds 服务的 Java 源码写的是
`13==14 && 15==16 && 15!=13`**（第 1、2 条相同 + 第 3、4 条相同），与字面语义不符。
两者必有一个是「笔误」：要么官方 Java 把条件写错（社区工具按语义修正），要么社区工具
改动了官方条件。**无法从代码判断哪边是本意**——这是规则语义分歧，不是实现 bug。

### 「新全节点 RPC 基因编码位置变化」假设：已证伪

1. hacds 官方仓库自带文档（rpc_service_api_en.md）中的老时代示例钻石
   KEATNH #36083（life_gene `66604b...a50f`，老系统入库 visual_gene `0fba51f6357d2d2f0850`），
   用**当前**全节点源码算法重算**逐字节一致**——编码格式从老 RPC 时代到现在没有变化；
2. 样本 390 颗覆盖 #453 ~ #138381（老/新时代混合），hacd.fun（当前全节点数据）与
   官方 Java 语义在 387/390 上完全一致——若编码位置变过，差异应大面积出现而非仅 3 颗；
3. NITVSB 本身是 #19474 的老钻石，其分差由规则条件不同精确解释，与数据新旧无关。

### Diamond_Analyzer v0.1.1 与 hacd.fun 评分完全同源

从其 PyInstaller 二进制（api_server_v2.zip）提取出 `lib/DiamondAnalyser.py` 全文，
与 hacd.fun 前端 ei 类逐条比对：**390 颗样本 0 分差**。共同差异（相对官方 Java）：
① Right mix pure 条件改为「后三位相同」；② Number Symmetry（回文编号 10 分）启用；
③ Symmetry→"Color Symmetry"、Half repeat→"ABCABC" 改名（条件分值同）。
另有独有处理：**score = max(1, score)**（0 分钻石抬为 1 分，见其 api.txt Notes：
"All diamond scores less than 1 will be set to 1"）。
数据来源：`GET {fullnode}/query/diamond?name=`，直接使用当前全节点返回的 visual_gene，
不做铭文判断（铭文仅用于结果分组展示）。

### 结论与待项目方决策

社区存在**两套评分方言**：官方 hacds 服务（Java）一套，hacd.fun + Diamond_Analyzer
（社区工具）一套，差异集中在 3 条规则。本预言机当时对齐官方 Java（HACDS 发行定价的
同源基准）。若项目方认定「右三混合」应按字面语义（1、3、4 条相同）计分，预言机与
合约需同步改 `get_styles` 的 Right mix pure 条件——一行改动，重跑交叉验证即可切换。

## 第三轮：基准切换为 Diamond_Analyzer v0.1.1（2026-10-19，项目方决定）

### 决定

项目方拍板：**评分规则以 Diamond_Analyzer v0.1.1 为准**（用户原话：「评分规则以这版
为准 https://github.com/arrake0101/Diamond_Analyzer/releases/tag/v0.1.1 ，这是当初
交易所使用的版本。本地官方 hacds 文件可以全部放弃，本来也只做提取评分规则用」）。
官方 `AnalyseDiamond.java` / `rule.txt` 不再作为基准，`OfficialCheck.java` 保留为
历史存档。HACDS 图标另从 nonkyc.io 提取（见 `assets/`），与评分无关。

### 预言机实现改动（hacds_oracle.py 评分内核整体切换）

| # | 改动 | 旧（官方 Java） | 新（DA v0.1.1） |
|---|---|---|---|
| 1 | Right mix pure 条件 | `13==14 && 15==16 && 15!=13` | `14==15==16 && 14!=13`（后三条相同） |
| 2 | Number Symmetry（回文编号） | 不计分（官方已注释） | **启用，10 分** |
| 3 | 改名 | "Symmetry" / "Half repeat" | "Color Symmetry" / "ABCABC"（条件分值同） |
| 4 | styles 位置规则 | 独立 if（可叠加命中） | **elif 互斥链**（首个命中生效） |
| 5 | 总分下限 | 无 | **`max(1, score)`**（0 分抬 1，DiamondManager 汇总层） |
| 6 | nameliteral 判定顺序 | rule.txt 出现顺序 | DA append 顺序（连击块 → Two/Three letters → ABCABC → Symmetric → AABCCD → ABBCDD） |
| 7 | numberliteral 判定顺序 | rule.txt 出现顺序 | DA append 顺序（Single num → Repetition → Serial → Number Symmetry → Tail 连击块） |
| 8 | tie-break 语义 | 等分取 rule.txt 先出现者 | 等分取先 append 者（`if score > max_score` 严格大于） |

tie-break 反转的固化用例：**77777 → Repetition**（旧：Tail five）、
**HMMMMH → Quadro repeat**（旧：Two letters）、**12321 → Number Symmetry 10 分**
（旧：Common 0 分）。

辅助函数对齐：`_max_run` 改为 DA `get_max_repeat_count`（无连击返回 1；连击块条件
`>=3`/`>=4` 使 1 与 0 观察等价）；`_shunzi` 改为 DA `is_sequential`（单字符返回 True；
此时 Repetition 50 必然夺魁，观察等价）；`_symmetry` 改为 DA `is_symmetric` 写法
（语义等价）；`_dark_or_light` 改为 DA `analyse_color_type` 双标志写法（语义等价）。

### 重验证结果（切换后）

基准 = 从 DA v0.1.1 PyInstaller 二进制（api_server_v2.zip）提取的 `lib/DiamondAnalyser.py`
原文件，直接 import 作为参考实现（含 DiamondManager 层 `max(1, score)`）：

| 对比 | 结果 |
|---|---|
| 预言机 Python vs DA 原版：390 颗主网真实钻石，总分 + 五维标签 | **390/390 一致（100%）** |
| 预言机 Python vs DA 原版：10,000 颗随机 fuzz，总分 + 五维标签 | **0 差异** |
| selftest（离线，22 项断言，含 6 项 DA 语义固化用例） | **全过** |

DA 语义固化用例：77777→Repetition、HMMMMH→Quadro repeat、12321→Number Symmetry、
0 分抬 1、NITVSB→Right mix pure 20（旧官方 3 分）、Pure 250。

### 结论

预言机评分内核已与 **Diamond_Analyzer v0.1.1** 逐条对齐：390 颗主网真实钻石 +
10,000 颗 fuzz，总分与五维标签 100% 一致。与 hacd.fun 前端（同源实现）亦 0 分差。
后续 FitSH 合约的链上 5 维重算必须按本报告的 DA 语义实现（设计文档 v2 第 2 节已同步）。
