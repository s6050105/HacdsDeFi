### 口径约定（★ 交接必读，UI / 交易所 / 合约三方一致性）

hacds 是 `decimal=8` 的链上资产，同一个 `amount` 存在**两种读法**，相差 **1e8 倍**：

| 读法 | 示例（用户某笔收款） | 用途 |
|---|---|---|
| **raw atoms** —— 链上 `amount` 原样 | `7000000000` | 浏览器显示、交易所接口、钱包**只读展示面板** |
| **人类个数** —— `amount / 1e8` | `70` | 钱包**操作区**（转账数量 / swap / 注入 的输入与计算） |

**约定（D44，2026-10-21）**：

1. **链上 / 交易所接口**：一律用 **raw atoms**。交易所读 `serial=2000` 的 `amount` 即为 raw；人类数量由消费方按 `decimal=8` 自除。
   > 浏览器实测（`explorer.hacash.org/tx/<hash>`）：显示为 `#2000 × 7,000,000,000`，**不标注小数位或单位** —— 即裸 raw。
2. **钱包 UI 分界**：
   - **只读展示面板** → **raw**（资产总览：已持有 / 待领取；协议状态：`amm:ds` / `pendDs` / `stakedDs` / `treDs` / `loan:coll`）
   - **不可写入操作区** → **÷1e8**（转账数量、`ds_in` / `min_out` / `ds_amt` / `share`）
3. **禁止全局改 raw**：操作区若改 raw，用户在输入框少写一个零就是 **1e8 倍**的资金误差。raw 只允许出现在**只读**位置。
4. **展示 raw 必须用大整数**：总供给 `5,963,298,700,000,000` 已超 `Number.MAX_SAFE_INTEGER`(9,007,199,254,740,991) 的 66%；JS 用 `BigInt` / 字符串化，Kotlin 用 `BigInteger`（**`Long` 不够**）。
5. 展示 raw 时**副标题必须注明口径**，不得把 raw 值标成「个」。

**链上核对值（2026-10-21 实测）**：

| 项 | raw atoms | ÷1e8 |
|---|---|---|
| 总供给 `supply` | `5963298700000000` | 59,632,987 |
| 合约地址持有 | `5963291700000000` | 59,632,917 |
| 用户钱包持有 | `7000000000` | 70 |

> 恒等式：`用户 + 合约 = 总供给`（用户持仓即已从合约赎回出去的部分）。改动任何一方的口径都不会改变这个守恒——换标度只是让两端同时变长。
