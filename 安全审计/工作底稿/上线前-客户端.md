# 工作底稿 · 上线前审计 · 客户端（PC + Android）

> 日期：2026-10-25 ｜ 范围：`wallet-app`（Electron 主进程/preload/渲染层/构建配置）、`android-app`（41 个 Kotlin + Manifest + Gradle + jniLibs）
> 方法：逐行审读 + 与冻结树 `D:\hacds` diff + 引擎源码（`D:\hacash_fullnode`）对照 + 离线复现 argv 错位

---

## 1. 总览

**核心结论：私钥保护是扎实的，但"被注入后能干什么"没有边界控制。**

私钥本身（不落盘、不进渲染层、不进 WebView、keystore 加密正确）经核实全部成立。问题集中在两处：

1. **渲染层到主进程的信任边界不存在** —— IPC 无参数校验、窗口无导航拦截。一旦渲染层被控，攻击者不需要私钥就能转走资金。
2. **Android 端交易构造整体失效**（A-1），且这是本轮新引入的回归。

## 2. A-1（Blocker）Android argv 错位 · 完整证据链

### 2.1 三方对齐表

| 层级 | 代码 | 参数序列 |
|---|---|---|
| 调用方 | `AppViewModel.kt:238` | `listOf(main, "0", c.contract, fnName, params)` |
| 组装 | `TxBuilder.kt:74-82` | `["hacds_txbuild", mode] + args` |
| 引擎期望 | `txbuild.rs:420,478,480,526` | `a[1]=mode, a[2]=main, **a[3]=ts**, a[4]=contract` |

`args` 不含 mode，所以 `args[2]` 在 argv 里是 `argv[4]`，而 `args[1]` 才是 `argv[3]`。

```kotlin
fixed[2] = ts ?: nextTs()     // ← 改的是 argv[4]
```

### 2.2 离线复现

```
输入 args  = [MAIN, "0", T1A8kae…, swap_hac_to_ds, 100]
组装后 argv= [exe, call, MAIN, "0", 1792469415, swap_hac_to_ds, 100]
                                   ↑          ↑
                              a[3]=0      a[4]=时间戳（应为合约地址）
```

引擎执行：

```rust
// txbuild.rs:526
let contract = Address::from_readable(&a[4]).expect("contract address");
// → panic: invalid address（时间戳不是合法 base58 地址）
```

`transfer` 模式：

```rust
// txbuild.rs:711
other => panic!("unknown transfer sub-form {other}")
// a[4] 本应是 "hac-to"，变成时间戳 → panic
```

### 2.3 失败如何呈现给用户

`txbuild::run()` 用 `catch_unwind` 捕获 panic，返回：

```
[ERROR] invalid address
```

`EngineOutput.parse()` 把任何 `[ERROR]` 行归到 `errorMessage` → `Built(ok=false, error="invalid address")`。

**用户看到的是 "invalid address"（英文、无上下文）**，而不是"交易构造失败"。这会让排障方向完全跑偏。

### 2.4 次生问题

| 问题 | 位置 | 说明 |
|---|---|---|
| `MODES_WITH_TS` 漏 `combo` | `TxBuilder.kt:36-39` | PC 的 `TX_MODES_WITH_TS`（`main.js:113-114`）含 `'combo'`。虽然 combo 也因 `fixed[2]` 错位而挂，但两者要一起修 |
| `nextTs()` 产生未来时间戳 | `TxBuilder.kt:58-62` | `maxOf(now, prev + 1)` → 同秒第二笔得 `now+1`；而 `main.js:88-92` 注释明确写"超前时间戳会被节点拒绝" |
| 时钟回拨兜底退化为复用 | `main.js:93-100` | 5 秒后放弃单调，回拨 `_lastTxTime` → 可能再次撞哈希 |

### 2.5 回归时间

`TxBuilder.kt` mtime `2026-10-25 14:00`，`main.js` mtime `2026-10-25 14:09` —— **同一天两端同时改时间戳注入，PC 改对、Android 改错**。冻结树 `D:\hacds` 的旧版 `build()` 无任何 ts 注入（`argv.addAll(args)` 直接拼），说明这是本轮新引入。

## 3. H-4 / H-5 渲染层到主进程的信任边界

### 3.1 链路

```
远端数据（明文 HTTP）
  ├─ 节点 /query/diamond     → name, visual_gene, belong, inscriptions
  ├─ 节点 /query/balance     → ticket, serial, amount
  └─ 索引器 /snapshot        → address
        ↓ 主进程原样返回（无字段校验）
        ↓ 渲染层拼 innerHTML（47 处，多处未转义）
  界面伪造 或 <meta refresh> 导航
        ↓ 无 will-navigate 拦截
  攻击者页面继承完整 window.api
        → buildTx + broadcast（转走资产）
```

### 3.2 未转义的实际位置（已逐条核实）

| 位置 | 拼接的远端字段 |
|---|---|
| `renderer/app.js:227-233` | `c.name`, `c.val`, `c.sub`（资产卡） |
| `:1017-1030` | `it.address`（清算表格，`data-a="' + it.address + '"` 引号可逃逸） |
| `:1946` | `i.name`, `i.score`, `i.vg` |
| `:1957-1975` | `dims.shapes / nameliteral / visual_gene / belong / inscriptions` |
| `:1639` | `modal` 的 `extraHtml` → `d.innerHTML` |

`esc()` 已定义（`:8`）且用于 error/hint/ret_val，**覆盖不全**是唯一问题。

### 3.3 IPC 暴露面

`preload.js` 暴露 30+ 方法，其中三个高风险：

```js
walletExportKey: () => invoke('wallet:exportKey')          // 已有 dialog 兜底
walletDelete: (req) => invoke('wallet:delete', req)        // filePath 无限制
httpGet: (req) => invoke('http:get', req)                  // url 无白名单
```

`main.js:1043-1053`：

```js
ipcMain.handle('wallet:delete', async (_e, { filePath }) => {
  fs.unlinkSync(filePath);      // ← 任意路径
```

`main.js:264-267`：`http:get` 直接 `httpGetJson(url)`，无域名限制 → 可读 `http://127.0.0.1:<port>/…`，结果可经 `buildTx`/`combo` 的错误回显带出。

### 3.4 修复

```js
// main.js createWindow() 内
win.webContents.on('will-navigate', (e, url) => {
  if (!url.startsWith('file://')) e.preventDefault();
});
win.webContents.setWindowOpenHandler(() => ({ action: 'deny' }));

// 所有 filePath 参数
const safe = path.resolve(filePath);
if (!safe.startsWith(walletsDir() + path.sep)) throw new Error('invalid path');
```

## 4. 其余发现

### M-10 明文 HTTP

`main.js:64`、`Config.kt:20-24` 默认全 `http://43.251.101.101:*`；`AndroidManifest.xml:19` `usesCleartextTraffic="true"`，无 `networkSecurityConfig`。所有余额/费率/清算/证书走明文，代码只做 `JSON.parse`。

### M-11 生物识别只是 UI 开关

```kotlin
// AndroidKeyVault.kt:41
.setUserAuthenticationRequired(false)   // 密钥访问不要求系统认证
```

`WalletScreen.kt:46` `var useBio by remember { mutableStateOf(false) }` —— 不持久化、重启复位、只在 UI 分支生效。**拿到已解锁设备可直接打开 vault 钱包转走资产。**

### M-12 Android 导出私钥无闸门

```kotlin
// AppViewModel.kt:427
fun exportKey(): String? = WalletSession.keyHex   // 无密码、无生物识别、无二次确认
```

对比 PC 已在 `main.js:1076-1095` 加了原生 `dialog.showMessageBox` 确认 —— **PC 修了、Android 没修**。且无 `FLAG_SECURE`，可被录屏/最近任务缩略图截取。

### M-13 密码框明文

`grep -c PasswordVisualTransformation` → **0 处**。`WalletScreen.kt:119,144,166` 三处密码/口令输入均为明文显示。PC 端 `modal()` 正确设了 `type='password'`（`app.js:1633`）。

### M-14 WebView `visual_gene` 注入

```kotlin
// DiamondImage.kt:33
val ok = visualGeneHex.length >= 19      // ← 只校验长度
// :86
private fun jsStr(s: String) = "'" + s.replace("\\","\\\\").replace("'","\\'") + "'"   // 不转义 <
```

`visual_gene` 来自明文 HTTP 的 `/query/diamond`。长度 ≥19 且含 `</script><script>…` → WebView 内执行任意 JS。

**缓解**：`blockNetworkLoads=true`、无 `addJavascriptInterface`、私钥不在 WebView → 危害限于本地信息探测/UI 伪造。

**与注释矛盾**：文件头 `:22` 写"JS 与网络均关闭"，实际 `javaScriptEnabled = true`（`:70`）。

### M-15 scrypt 参数无上界

```kotlin
// Keystore.kt:88
Scrypt.derive(password, salt, j.getInt("n"), j.getInt("r"), j.getInt("p"), j.getInt("dklen"))
// Scrypt.kt:20
val v = IntArray(n * words)      // n, r 完全来自文件
```

只校验 `n` 是 2 的幂、`r/p > 0`。构造 `n=2^27` 的 keystore JSON → 打爆堆，或 `n*words` 溢出成负数 → `NegativeArraySizeException`。

PC 侧 `crypto.scryptSync` 有 `maxmem: 256MB` 兜底（会抛错不会 OOM），风险较低。

### M-16 发布签名配置

```
android-app/keystore/hacds-release.jks      2630 字节，在工程目录内
build.gradle.kts:57  isMinifyEnabled = false      → proguard 规则形同虚设
build.gradle.kts:62  enableV1Signing = true       → minSdk 24 下无必要，扩大旧签名方案攻击面
```

**口令来源是正确的**（`HACDS_KS_PASS` 环境变量 / 未入库的 `keystore.properties`，仓库内无硬编码）。问题只在文件位置与混淆。

### M-8（口令派生钱包）

```js
// keystore.js:36-38
function secretFromPassword(password) {
  return sha256(Buffer.from(password, 'utf8')).digest();
}
```

"口令钱包"的**私钥本身**就是 `sha256(口令)`，无盐无拉伸（scrypt 只用于外层文件加密）。任何拿到地址的人可离线穷举；6 位口令在 GPU 上瞬间可破。

这是 Hacash `create_by` 的协议兼容约束，**不是实现 bug**；但产品层未做任何强度门槛或警示。

### L-01 开发脚本进 asar

`package.json:29` 的 `"renderer/**/*"` 匹配到 `renderer/_fix3.py`、`_unify.py`；`extraResources` 还打包了从未被引用的 `bin/hacds_oracle.py`。

### L-02 / L-03 / L-04

- `AppViewModel.kt:327-331`：清算地址 `take(12)` 落 logcat；
- `AppViewModel.kt:477-482`：签名后交易体写 `getExternalFilesDir`（`/sdcard/Android/data/…`），部分 ROM 可被他人读取 → 未上链的交易可被抢先广播；
- `MainActivity` 导出 + `lang` extra 可被任意应用触发 `Runtime.getRuntime().exit(0)`（DoS/骚扰）。

## 6. 无法热修的风险提示

`app.on('autoUpdater')` 与 `crashReporter` 均未使用（grep 0 次）。这意味着：

- **H-4 / H-5 一旦发版就必须靠用户手动升级才能修**；
- 本次 D-1（HACD 功能全挂）同样无法推送热修。

**建议**：若时间允许，在首个正式版之前就把 `will-navigate` 拦截与 `esc()` 补全做掉 —— 这两项改动极小，但一旦带着它们发版，后续修复成本会高一个数量级。
