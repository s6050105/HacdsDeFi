## 2. 发现

### A-1 ｜ **Critical** ｜ 预言机证书可伪造评分——`SECURITY.md §2.5` 的承诺不成立

**证据**
- 合约 `verify_cert`（`HacdsDeFi.fitsh:720-740`）：
  - `vg = buf_cut(msg, 6, 10)`、`num = buf_u64(msg, 16)`、`claimed = buf_u32(msg, 24)` —— **vg/num 取自证书**；
  - 只校验：size==29、版本、`name` 与转移名单一致、预言机签名、（用**证书里的 vg/num**）重算分 == claimed；
  - **没有任何「按 name 从链上读真实 visual_gene/number」的步骤**（且 VM 未提供该能力，见 §1）。
- 预言机侧（`hacds_oracle.py:632-645`）确实是按 name 查节点、并交叉校验派生 vg——但那是**链下**的可信假设，不构成链上约束。

**影响**
被持预言机私钥者（或攻陷预言机进程/服务器者）签发的证书，可携带**任意 vg/num**。合约无法察觉，只要重算分 == claimed 即接受。
→ 攻击者用**一颗无价值的 HACD**（真实转移以通过 `check_hacd_wire` 与 name 匹配），配一份伪造高分的证书，即可在 `PayableHACD` 记账 `due = score × 10⁸`，**凭空铸出巨额 hacds 配额**。这是「铸币/储备被掏空」级后果。
**这与 `SECURITY.md §2.5`「A fully compromised oracle still cannot forge a score」直接矛盾**——该句对链上机制的理解有误。

**最小复现（思路，需预言机私钥）**
1. 取任意自有 HACD（名字 A，低分）。
2. 构造证书：name=A、vg=高分位、num=加分编号、score=合约对该 vg/num 的重算值；用预言机私钥签名。
3. 发交易：把该 HACD 转入合约并附该证书 → `PayableHACD` 通过 → `due[A] += score×10⁸`。

**修复建议**
- 若 VM 无法读基因，则「链上重算」**不能**替代预言机信任，必须改为**显式承认预言机为信任根**，并据此：
  1. 更正 `SECURITY.md §2.5` 与 README 的表述（去掉「预言机失陷也无法伪造评分」）；
  2. 把预言机键的**保密与可用性**提升到与合约同级（HSM/隔离机、最小暴露、轮换预案）——当前它与公网可写的节点/服务同处一台服务器（见 F-002/F-003）；
  3. 合约侧加**结构性约束**降低单点危害：如按 score 设上限、按 name 唯一性/首次登记防重复申领、或引入第二个签名者阈值。
- 若未来 VM 开放「按 name 读基因」原语，应改为链上直取基因，彻底移除对证书 vg 的信任。

> **项目方决定（2026-10-22）**：**记为已知悉**。预言机地址为合约内固定地址、私钥仅在服务器、未公开 → 外部伪造证书的概率被压低。据此**风险按已接受处理**，但**设计缺陷本身不消除**：`§2.5` 的表述仍是错的（链上无法核对真实基因），文档更正建议保留。A-1 保持 **Critical（已接受）** 评级。

### A-2 ｜ **High** ｜ 借贷抵押估值用 AMM 现货价，可被操纵

**证据**
- `coll_to_hac(coll)`（`:1221-1226`）= `coll × amm:hac / amm:ds`，即**即时池价**。
- 借款额度（`:1291-1292`）与清算触发（`:1351-1355`）**都用它**。
- AMM 池价由任何人的 `swap_*` 直接推动（`:927-964`），无 TWAP、无时间加权、无滑点外保护。

**影响**
- 攻击者（含闪电贷式、或大资金）可**临时压低池价**→ 目标贷款「健康度」跌破 200 → 触发 `loan_liquidate`，清算人（攻击者）取得最多 10% 抵押奖励；
- 或**临时抬高池价**→ 以虚高的抵押价值**超额借款**，随后价格回归。
- 因合约不可升级，此风险上线即固化。

**修复建议**：改用 TWAP / 多源价格（如预言机额外提供价格并做时间加权）；对清算加「价格偏差 + 时间确认」双条件；限制单块内价格对借贷判定的影响。

### A-3 ｜ **High** ｜ 违约时债务直接核销、不回收真币 → 合约 HAC 储备可被抽干

**证据**
- `loan_borrow`（`:1299-1303`）把借款额直接记给借款人 HAC 积分，并 `total_add(0, hac_amt)`，配合同笔 `TransferHacFromTo` 让借款人拿到**真币 HAC**。
- `loan_liquidate`（`:1364-1377`）把 `debt` 与 `coll` **直接置 0**，只把 `bonus`（抵押的一部分）记给清算人；**没有任何向借款人追偿真币 HAC 的路径**。
- 抵押品是 `due` 配额（纸面），清算是**核销**而非变现回收。

**影响**
借款人收到的真 HAC 来自合约储备（其他用户存入的 HAC）。一旦违约，合约承担该笔 HAC 损失；抵押品的清算只是纸面再分配，**不补充真币 HAC**。与 A-1/A-2 组合，可被主动攻击为大额抽干：伪造分/操纵价 → 低真实成本取得高额抵押 → 借出真币 HAC → 违约走人。

**修复建议**：清算必须包含「把抵押变现为真币 HAC 回补合约」的路径（或在借贷前对抵押做真币级约束）；设借款总额上限与储备覆盖率下限；对单账户/单笔借款设上限与冷却。

### A-4 ｜ **Medium** ｜ 管理员可将清算奖励设为 0 → 清算失去激励 → 坏账累积

**证据**：`set_liquidate_bonus`（`:1463-1468`）允许 `bps ∈ [0,1000]`；`loan_liquidate` 的奖励即 `coll × bonus_bps / 10000`。`bonus_bps=0` 时清算人无所得。
**影响**：管理员（或误操作）置 0 后，无人有动力清算，坏账堆积（叠加 A-3 的核销问题）。同理 `set_loan_rate=0`（无息）、`set_fee=0`（AMM 回退默认费，见 `:934-938`）。
**修复建议**：为清算奖励设**非零下限**（如 ≥50bps）；关键参数变更加时间锁/事件。

### A-5 ｜ **Medium** ｜ 存储键过期 → `storage_load` 抛错 → 相关操作整笔回滚

**证据**
- 账本读写用 `storage_load`/`wr_u128`；注释（`:554-555`）明确：键进入 `recoverable` 会报 `StorageNotActive(108)`，需管理员 `rent_batch` 续租。
- `rent_batch`（`:1477-1497`）需管理员**显式给出键清单**，合约/节点无「按前缀枚举」能力（见索引器设计文档）。

**影响**：任一账本键过期而未被续租，则触及它的用户操作**整笔回滚**（可用性受损，不丢币）。管理员需人工维护全部活跃键清单，遗漏即故障。SECURITY.md 未披露此项。
**修复建议**：文档化并给运维 SOP（定期扫描活跃键续租）；在 `serve` 侧增加「临近过期键」巡检与告警；或提高关键账本键租期上限（受 gas 约束，见常量注释）。

### A-6 ｜ **Low** ｜ 清算为「全额」清算，无部分清算与额度下限

**证据**：`loan_liquidate`（`:1344-1379`）一次性把 `debt`、`coll` 全清。
**影响**：大额抵押账户一旦越线即被**全额**清算（而非按需部分清算），对用户更严苛；亦无「奖励 ≥ 最小额」的门槛，小额清算可能因 gas 不划算而无人执行。
**建议**：引入部分清算比例与最小清算额。

## 4. 阶段结论（P0-1 完成）

- **会计管道与 AMM 数学自洽**：不变式（Σbal==tot、settle 增益 total_add）、边界（首注防尺度重置、费分配、清算记账）均已处理，算术无溢出（`mul_div` 用 256 位宽乘 + 超界报错，已核）。
- **HVM 语义复核**：无跨合约再入路径（转账为独立顶层动作、MainCall 为 AST scope）；`mul_div` 边界安全；`loan_status` 与清算门槛、索引器判定三方一致。
- **核心风险在信任模型**：
  - **A-1 Critical（已接受）**：链上无法核对证书里的真实基因 → 预言机私钥即铸币权；`SECURITY.md §2.5` 表述错误须更正。
  - **A-2/A-3 High**：现货价抵押估值 + 违约不回收真币 → 可抽干合约 HAC 储备。
  - A-4/A-5 Medium、A-6 Low、A-7 Info。
- 因合约**不可升级**，A-1~A-3 的整改意味着**重新部署 + 重发资产**；在文档层面，至少应立刻更正 `§2.5` 的错误承诺。
- **剩余待办（非阻塞）**：用 `fuzz_vectors.txt` 做合约↔预言机评分逐条机器比对（列入 P0-2）。
