## B. 评分预言机（`hacds_exchange/oracle/hacds_oracle.py`，918 行）

### 审读结论：整体设计良好，无致命缺陷

| 检查项 | 结论 |
|---|---|
| 是否提交交易 | **否**（无 `/submit`）——线上探测也证实只有 `/health`、`/cert` |
| 私钥注入 | `load_privkey`：**环境变量优先**，其次 `--key-file`；**明确拒绝命令行明文私钥**（防 shell history / 进程列表） |
| 私钥文件权限 | `cmd_genkey` 以 `0o600` 创建并 `chmod`；文档要求 0600、属主运行用户 |
| 密钥是否入日志 | `log_message` 只记 HTTP 行；错误走 `{"error": str(e)}`，**不含私钥**。未见泄漏 |
| `--expect-address` | 出证前校验密钥地址 == 链上 `cfg:oracle`，**防装错密钥**（安全闸） |
| `/cert` 输入校验 | `name` 必须 6 字符，否则 400；`issue_certificate` 内 vg 派生与节点值交叉校验 |
| 证书可重放性 | 证书内容为 `name+vg+num+score+ver` + 签名；合约按「转入的钻石名字」匹配证书 idx——**同一颗钻石的证书可在多笔存入中重复使用**（因为合约拿不到「该钻石是否已兑换过」的链上状态）。这是设计使然，与 A-1 同源，不单列 |

### B-1 ｜ **Low–Medium** ｜ `/cert` 无鉴权、无限流
- 与 F-003 同项。证书公开可算、不泄密；风险是 DoS 打挂服务 → **兑换可用性中断**（`SECURITY.md §3.3` 自认单点）。
- 修复：反代限流 / 白名单；或接受（已文档化）。

### B-2 ｜ **Info** ｜ 与 A-1 的关系
预言机**可信假设成立**（只读签名、私钥隔离、地址固定），但 A-1 已指出：**链上并不核对证书里的真实基因**，因此预言机私钥在语义上等同「铸币权」。`SECURITY.md §2.5` 表述需更正（见 A-1）。

## C. 链下索引器（`hacds_indexer.py`，434 行）

### C-1 ｜ **High（已修复）** ｜ 写接口公网可写
- 见 F-001：`/sync`、`/watch/add`、`/watch/remove` 原为公网匿名可调。**已按方案 A 部署只读版并线上复测（读口 200 / 写口 403）**。

### C-2 ｜ **Low** ｜ `Access-Control-Allow-Origin: *`
- 任意网页可读取台账（`/watchlist`）。无跨域需求时应收紧（F-004）。

### C-3 ｜ **Medium** ｜ 台账被钱包**无条件信任**，无响应校验
- 索引器维护「清算观察台账 + 实时健康度」，钱包 PC/Android 直接采信。
- 索引器本身是**单一公网服务**；若其被篡改/劫持，可向钱包推送**伪造的清算列表**（误导用户执行清算或误判风险）。与 D-2 同源。
- 修复：钱包侧对台账做基本一致性校验（如 `health`/`debt`/`coll` 与自行 sandbox 查询交叉核对）；或对索引器响应做签名/HTTPS+证书固定。

### C-4 ｜ **Info** ｜ 扫链一致性
- `sync()` 以 `last_scanned+1..head` 增量扫描；**未处理 reorg**（重组会使已记台账高度错位）。因台账是「地址集合 + 首次/末次高度」的宽松统计，影响有限，但极端重组下健康度快照仍以实时 sandbox 重算为准（`snapshot()` 每地址实时查 `loan_status/debt/coll`），故**误导风险低**。记录为待观察。

## D. PC 钱包主进程（`main.js` 1050 + `preload.js` 53 + `keystore.js` 93 + 其余）

### 正面确认（与 `SECURITY.md` 承诺一致）

| 承诺 | 核实 |
|---|---|
| 私钥不触网、不落盘 | ✅ 会话内 `sessionKeyHex` 仅在主进程内存；以 `HACDS_SIGN_KEY_HEX` 注入子进程；**未见写入磁盘**（除用户主动「导出私钥」） |
| 不使用 `/util/transaction/sign`、`/create/coin/transfer` | ✅ 全仓 grep 仅在**设计文档**中出现（说明"禁用"），代码未调用 |
| Renderer 隔离 | ✅ `nodeIntegration:false`、`contextIsolation:true`、`preload` 白名单、CSP `default-src 'self'; script-src 'self'`（无 `unsafe-inline`） |
| Keystore | ✅ scrypt N=2^15/r=8/p=1/dklen=32 + AES-256-GCM + AAD `hacds-keystore-v1`，实现正确 |

### D-1 ｜ **Medium** ｜ 渲染层把**节点/索引器返回文本直接 `innerHTML` 注入**（UI 欺骗面）
- 证据：`renderer/app.js:1400`（交易翻译）：
  ```js
  box.innerHTML = `<b>${t('common.translTitle')}</b>: ${d.description ...}` +
      (d.actions||[]).map(a => `  [${i+1}] ${a.description || JSON.stringify(a.action)}`).join('\n');
  ```
  同类 sink 见 `:785/1052/1056/892/1142/1236` 等（`r.error`、`r.hint`、节点 `ret_val` 文本均未转义）。全文件 **46 处 `innerHTML`**。
- **可利用性**：内容来自用户自配的**节点 RPC**——攻击者需先控制节点（或中间人）。属「自配节点即可被其污染 UI」。
- **为何是 Medium 而非 High**：CSP `script-src 'self'` 且无 `unsafe-inline`，**注入的 `<script>`/内联 on* 不会执行**；当前影响限于**伪造错误/预览文本**（可在界面显示任意说明、伪造链接诱导点击）。
- 修复：所有远端文本改 `textContent`，或统一封一个 `esc()` 转义；保留 CSP。

### D-2 ｜ **Medium** ｜ 不校验节点/索引器响应
- `http:get`（`main.js:223`）与 `srvGet`（`:729`）把响应直接 json 解析即用，无签名/来源校验；清算台账采信索引器（`liq:snapshot`/`liq:sync`）。
- 影响：恶意/被劫持的节点或索引器可返回伪造数据误导界面（与 C-3/D-1 同一信任面）。
- 修复：对关键数值做交叉核对（如自行 sandbox 比对）；索引器启用 HTTPS + 证书固定。

### D-3 ｜ **Low–Medium** ｜ `wallet:exportKey` 把明文私钥返回渲染层，仅前端 `confirm()`
- `main.js:960`：`if (!sessionKeyHex) reject; return { keyHex: sessionKeyHex }`——**主进程不要求重输口令或生物识别**；门禁仅在渲染层 `confirm(t('w.exportConfirm'))`（`app.js:1555`）。
- 影响：私钥明文进入渲染层 DOM（用户可见即所需），但门禁可被渲染层 XSS/脚本绕过（当前被 CSP 缓冲）。属**设计选择**（离线冷签需导出），但建议：
  1. 主进程二次鉴权（重输钱包口令 / 触发系统生物识别）后再返回；
  2. 导出内容只在必要弹窗内以 `textContent` 呈现，避免二次落 DOM 文本节点被扩展读取。

### D-4 ｜ **Info** ｜ `sandbox:false`
- Electron 渲染沙箱关闭。因 `nodeIntegration:false` + `contextIsolation:true`，风险有限；建议开启 `sandbox:true` 作纵深防御（需确认 preload 兼容）。

### D-5 ｜ **Info** ｜ 广播前核对
- `tx:translate`（`/util/transaction/check?description=true`）与预览面板提供翻译；但**广播本身不强制**先翻译（`pvSend` 只做 hex 校验）。`SECURITY.md §3.7` 建议「广播前用 Translate」，属流程建议而非强制。记录。
