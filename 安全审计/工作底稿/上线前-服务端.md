## 2. 索引器 · 详细证据

### C-1（Blocker）写接口默认开放 —— 见主报告 §2

### H-1 `rent_batches` 静默截断

**代码**（`:447-460`）：

```python
raw = bytes.fromhex(g["blob"])
n = len(raw) // klen
if n > 50:                     # 与本批键数上限对齐（索引器侧保护）
    n = 50                     # ← 截断总数，不是限制每批
for i in range(0, n, max_keys):
    part = raw[i * klen: min(i + max_keys, n) * klen]
```

**离线复现**：

```python
# 60 个地址 × 4 种前缀 = 240 键
真实键数: 240
输出批数: 15 批 × 10 键 = 150
丢失:     90 键（每个地址的 ln:/ck: 全部丢失）
```

**为什么致命**：`rent_keys_group()`（合约 `:2590`）只覆盖 7 组固定键长，**按地址键必须由这个接口提供**。漏掉的键过期后 → `StorageNotActive(108)` → 该用户所有操作回滚。

### H-2 keeper 的 `_value_len` 键长判断错误

**代码**（`hacds_keeper.py:84-92`）：

```python
def _value_len(klen: int, blob_hex: str) -> int:
    if klen == 23:
        prefix = bytes.fromhex(blob_hex)[:2]
        if prefix == b"ck": return 64      # 不可达
        return 48
    return 16                              # klen=24 的 ln:/ck: 落这里
```

**实测键长**：

| 前缀 | 键长 | 值长 | 代码判定 |
|---|---|---|---|
| `u:` | 23 | 48 | ✅ 48 |
| `ln:` | **24** | 48 | ❌ 16（低估 3 倍） |
| `ck:` | **24** | 64 | ❌ 16（低估 4 倍） |
| `bad:` | 25 | 16 | ✅ 16 |

**真实成本 vs 单桶上限 111,911**：

```
ln: × 5 = (48+20)×300×5 = 102,000  ✅ 刚好
ln: × 6 = 122,400                  ❌ OutOfGas
ck: × 4 = (64+20)×300×4 = 100,800  ✅ 刚好
ck: × 5 = 126,000                  ❌ OutOfGas
```

而索引器 `/rent_batches?max` 默认 10、上限也钳到 10，keeper 用错误 cap 认为"不用切" → **必然整笔回滚**。

**附带死代码**：`:78-81` 的 `VALUE_LEN_BY_KLEN` 定义后全文未引用（grep 确认），且同样把 `ck:` 记成 23。

### H-3 状态文件损坏静默清零 + 并发写竞态

**静默清零**（`:125-133`）：`except Exception: pass`。

**竞态**（三点叠加）：

1. `save()` 用固定 `state_file + ".tmp"`：两个线程同时 `open(tmp,"w")` → 互相截断；
2. `add()`/`remove()` 在 `with self.lock` **之外**调 `save()`，而 `save()` 遍历 `self.watch`/`self.chain` 无锁；
3. `sync()` **整体无锁**：poller 线程（每 60s）与 HTTP `/sync` 可并发，`_append_chain` 的 `self.chain = [...]` 与 `sorted(self.chain)` 直接竞争，`last_scanned` 互相覆盖。

三者任一触发 → 写坏文件 → 又被 `except: pass` 清零。**形成自洽的"台账消失"路径。**

### M-1 keeper 签名护栏被击穿

```python
if "signed_tx_hex" in line:            # ← 子串！
    signed = ...
elif "unsigned_tx_hex" in line:        # ← 死代码
    unsigned = ...
```

**实测**：`"signed_tx_hex" in "unsigned_tx_hex=AAAA"` → `True`。若 txbuild 只输出 unsigned（签名失败但退出码 0），`signed` 被赋成未签名体 → 后续 `if not signed: raise` 不触发 → **广播未签名交易**。

### M-2 `/watch/add` 无校验 + `caller` 未编码

```python
a = (qs.get("address") or [""])[0].strip()
if not a: return self._send({"ret":1,"err":"address required"}, 400)
IDX.add(a, (qs.get("note") or [None])[0])
```

- 不校验 base58check、不限长、不限量 → 台账无界增长，每次 `add` 重写全量 JSON；
- `_call()`（`:316-320`）把地址直接拼进 `caller=`（`params` 有 quote，`caller` 没有）→ `address = "x&params=…&function=…"` 可向 `127.0.0.1:8082` 注入 query。

### M-3 单线程 + 无 timeout

`HTTPServer((host, port), Handler).serve_forever()`（`:671`）—— 非 `ThreadingHTTPServer`；`BaseHTTPRequestHandler` 未设 `timeout`。一条不发完请求头的慢连接即可占满唯一 acceptor。`/watchlist` 对每地址串行 3 次 sandboxcall（每次 15s×3 tries）。

### M-4 CORS `*` + GET 写接口

`Access-Control-Allow-Origin: *`（`:505`）。写操作是 GET（CORS 简单请求，**免预检**）→ 任意网页可跨站发起 `/watch/remove`。同仓 `hacds.com/worker/index.js` 用的是来源白名单，是正确写法。

### M-5 扫链 selector 子串匹配 + 视图函数误计入

```python
for sig, name in LOAN_SELECTORS.items():
    if sig in hx:          # ← 任意位置子串命中，且不校验目标合约
        return name
```

`LOAN_FNS`（`:49-52`）含 `loan_status` / `loan_debt_of` / `loan_coll_of` 三个**只读视图** → 任何人调一次就被记成"借款行为"塞进观察名单。

### M-6 root 运行

`hacds_indexer.service:12` `User=root`，无 `NoNewPrivileges` / `ProtectSystem` / `PrivateTmp`；日志 `append` 无轮转（撑满磁盘会触发 H-3）。

### L-5 reorg 回退不减 `fns`

`_record(delta=-1)`（`:184-193`）只减 `calls`，不减 `fns[fn]` → 重扫后 `fns` 永久虚高。

### L-7 相对路径 state 永不落盘

`save()`（`:138`）：`os.makedirs(os.path.dirname(state_file))`，当 `--state watch.json`（无目录）时 `dirname` 为 `""` → `makedirs("")` 抛错 → 被 `except` 吞 → **状态永不落盘，重启即丢台账**。

### I-1 定时炸弹死代码

`:436`：`"keys": [prefix_label(k) if False else k.hex() for k in keys]` —— `prefix_label` **未定义**，靠 `if False` 短路。任何人"清理"这个 `if False` 就会 `NameError`。

## 3. keeper · 补充

### M-8 签名批次内容由远端明文 HTTP 决定

```python
DEFAULT_INDEXER = "http://43.251.101.101:8124"
DEFAULT_NODE    = "http://43.251.101.101:8082"
```

`blob`（要写入的键字节）与批次数完全由索引器返回，走明文 HTTP，无签名无校验；keeper 用它构造并用本地私钥签名广播。

**危害边界（已核实）**：`blob` 是 hex（`bytes.fromhex` 拒非法字符），拼进 `params` 时无法注入 `:`/`,` → **不能改写函数名或金额**。风险限于"租哪些键 + 花多少 gas"，且**花的是 keeper 自己的钱，不是金库** —— 金库按每键 0.07 HAC 付酬，脚本无法超额领取（合约 `:2350-2360` 按 `paid` 计数封顶）。

**修复**：默认改 `127.0.0.1`；校验 `klen ∈ {23,24,25}`、前缀命中白名单、`len(blob) == klen×n`；批次总数硬上限。

### L-8 `--period` 无上限

只校验下限，`topup --period 1e9` 会让单笔 storage 成本远超预算（OutOfGas，只烧手续费）。

## 4. 预言机 · 补充

### M-9 硬编码 `0.0.0.0` + 无鉴权 + 回显异常

`hacds_oracle.py:783-785`：`HTTPServer(("0.0.0.0", args.port), ...)`，无 `--host`；`except Exception as e: self._reply(502, {"error": str(e)})` 把上游 URL 与 Python 异常原样回给客户端。

**缓解事实**：证书内容 100% 可由 `name + life_gene` 复算；#3000 已删预言机，**该私钥无链上权力** → 剩余风险仅可用性与信息暴露。

**建议**：既然 #3000 不需要，直接把该脚本从发布包移除（`wallet-app/bin/` 那份也不要随安装包携带）。

### L-2 密钥环境变量名不一致

代码读 `HACDS_ORACLE_KEY`（**原始私钥 hex**），部署文档 `部署说明-服务器.md:85` 写的是 `HACDS_ORACLE_KEY_FILE`。

- 按文档配置 → 代码读不到 → 启动失败（可见，不危险）；
- 反过来把私钥塞进 `HACDS_ORACLE_KEY` → 进 `/proc/<pid>/environ`、crash dump、`systemctl show`。

**修复**：只保留 `--key-file`，删除环境变量注入原始私钥的分支；文档同步。

### L-3 `genkey` 覆盖已有私钥

`:711-719`：`O_TRUNC` 直接覆盖；`os.chmod` 失败被 `except OSError: pass` 吞（Windows 上无效果）。
