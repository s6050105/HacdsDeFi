## B. 官网（`hacds.com/`，未上线）

### B-0 结论

纯静态站，无构建、无依赖。**三处功能级缺陷**：金额换算放大 1e8（B-1 见主报告）、HACD 掉用不存在的合约函数、`/api/build` 后端不存在。

### B-1 HACD 存入/赎回调用不存在的合约函数

**位置**：`assets/js/txbuild.js:131-138`

```js
async function mintHacd(main, name) {
  return build('deposit_hacd', [{ v: name, t: 'bytes' }], main, { gasMax: 99 });
}
async function redeemHacd(main, name) {
  return build('redeem_hacd', ..., { gasMax: 99 });
}
```

**核实**：

```
grep -c "function external deposit_hacd(" HacdsDeFi3000.fitsh  → 0
grep -c "function external redeem_hacd("  HacdsDeFi3000.fitsh  → 0
grep -c "function external deposit_hacd(" HacdsDeFi.fitsh      → 0
```

旧版 #2000 也没有这两个函数 —— HACD 收支是**抽象钩子**（`PayableHACD`/`PermitHACD`），由 `TransferHacdTo`/`TransferHacdFromTo` 转账动作触发，不是 `MainCall`。

**正确做法**（对齐 PC 钱包 `main.js` 的 `mode: 'hacd'`）：

```js
// #3000 无证书：hacd 模式需要适配 —— 引擎当前 "hacd" 分支强制读 certfile
txbuild.rs:545  let cert_path = a.get(6).expect("...certfile");
txbuild.rs:557  assert_eq!(cert.len(), names.length() * 126, ...);
```

⚠ **重要**：引擎 `hacd` 模式**仍然要求 126B 证书流**（`txbuild.rs:543-560`），而 #3000 已删除证书。因此：
- 要么给引擎加一个"无证书"模式（`hacd-nocert`）走纯 `TransferHacdTo`；
- 要么官网与 PC 钱包的 HACD 存入功能 **#3000 上线时必须禁用**，直到引擎适配。

**这是跨模块的阻断性缺口，主报告已列为 M-7，但严重度应上调为 High —— 它同时影响 PC 钱包与 Android。**

复核 PC 钱包：`renderer/app.js:1391` `op.kind === 'redeem'` → `main.js:750` `mode: 'hacd'` → 同样读 cert。Android `AppViewModel.kt:388` 同样传 `certFile`。**三端都没适配 #3000 的无证书路径。**

### B-2 `/api/build` 后端不存在

`worker/index.js:77-79`：`BUILD_ORIGIN || NODE` → 转发到 Hacash 节点 `/api/build` → 节点无此路由 → 404。`README.md` 已承认"该服务目前尚未在公网暴露"。

**后果**：官网所有写操作（swap/add/remove/borrow/repay/collateral）在 txbuild.js 中**全部依赖这个端点**（`build()` 是唯一出口）→ 官网 DeFi 控制台**完全不可用**，只能读链上状态。

### B-3 无 CSP / SRI

`index.html`、`app/index.html`、`docs/index.html`、`whitepaper/index.html` 四页 `Content-Security-Policy` 均为 0 处。`i18n.js:618`：

```js
if (v.indexOf('<') >= 0) el.innerHTML = v;
```

词条是本地静态数据，当前无远端注入点；但 `markdown.js` 的 `<!--ARCHFIG-->` 块**原样输出不转义**（`:38-48`），而白皮书 md 由 `fetch` 加载 —— 若 md 托管被改，可注入任意 HTML。

### B-4 官网与客户端的口径不一致（交叉核对表）

| 量 | 合约 | 官网 | PC 钱包 | Android |
|---|---|---|---|---|
| hacds 计数 | atoms（decimal=0，1:1） | ❌ ÷/×1e8 | ✅ 原值 | ✅ 原值 |
| HAC | zhu（1 HAC = 1e8 zhu） | ✅ ÷1e8 | ✅ ÷1e8 | ✅ ÷1e8 |
| pool_price | zhu per atom | ✅ ÷1e8 显示 | ✅ ÷1e8 | ✅ ÷1e8 |
| ref_price_of | zhu/atom ×1e8 | 未使用 | 用 `ref_price_zhu_per_ds` | 同 |
| LP 份额 | 无定标 | ✅ 原值 | ✅ 原值 | ✅ 原值 |

**只有官网一行是错的。**

### B-5 正面确认

- `wallet.js` 只做 `connect / wallet / signtx`，**从不接触私钥**，职责边界清晰。
- Worker 的 CORS 用**来源白名单**（`corsHeaders`），不是 `*` —— 这是索引器应当对标的正确写法。
- `markdown.js` 除 `ARCHFIG` 特殊块外，全部内容走 `esc()`。
- `config.js` 的 `useLocal` 只在 `localhost/127.0.0.1` 生效，不会在线上误降级为明文直连。
