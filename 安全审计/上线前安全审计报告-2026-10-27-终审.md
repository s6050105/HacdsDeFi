## 2. 阻断级发现

### E-1 【Blocker·新引入】官网 HACD 返回 `ok:false` 未被消费，错误信息被吞

**位置**：`hacds.com/assets/js/txbuild.js:155-172`（新增）与 `app.js:581, 650`（未同步）

`txbuild.js` 现在明确拒绝 HACD 操作：

```js
async function mintHacd(main, name) {
  return {
    ok: false,
    error: '官网暂不支持 HACD 存入，请使用桌面钱包或 Android 应用（该操作需要多动作交易）',
    unsupported: true,
  };
}
```

但 `app.js` 仍按旧契约使用：

```js
const res = await TX.mintHacd(S.addr, name);
await sendTx(res, '[' + (i+1) + '/' + names.length + '] 存入 ' + name,
             { msglayout: W.HACD_CERT_LAYOUT });     // ← 不检查 res.ok
```

`sendTx` 内部：

```js
const r = await W.signTx(res.txbody, opts);   // res.txbody === undefined
```

**实测调用链**：

```
res = {ok:false, error:'官网暂不支持…', unsupported:true}
res.txbody            → undefined
W.signTx(undefined)   → MoneyNex 收到 txbody: undefined
                      → 返回与「官网不支持」完全无关的错误
```

用户在批量存入时，会看到 N 条「失败：<钱包的原始错误>」，而不是设计者写好的那句中文提示。**`unsupported` 字段写了但从未被读取**（`grep unsupported app.js` 零命中）。

**修复**（3 行）：

```js
const res = await TX.mintHacd(S.addr, name);
if (res && res.ok === false) {
  log(res.error || '该操作暂不支持', 'warn');
  break;                     // 批量时直接停，不必逐颗重试
}
await sendTx(res, ...);
```

更彻底的做法：HACD 面板在 `mintHacd` 不可用时直接禁用按钮并显示原因，而不是让用户点完才报错。

### E-2 【Blocker·构建流程】随包二进制未重建，且校验和/文档仍指向旧版

**实测证据**：

| 对象 | 时间 | 行为 |
|---|---|---|
| 引擎源码 `testkit/src/txbuild.rs` | **2026-10-26 00:34** | 已支持 certfile 可选 |
| 引擎构建产物 `target/release/hacds_txbuild.exe` | 2026-10-26 00:35 | 实测正常：`hacd: … cert=none(#3000)` |
| `wallet-app/bin/hacds_txbuild.exe` | **2026-10-21 01:49** | 实测 **panic，exit 127** |
| `android-app/.../libhacds_txbuild.so` | **2026-10-22 04:06** | 未重建 |
| `wallet-app/dist/win-unpacked/resources/bin/` | 2026-10-21 | 仍是旧二进制 |

**实测对比**（同一命令，不带 certfile）：

```
旧（随包 10-21）：
  thread 'main' panicked at hacds_txbuild.rs:460:38:
  usage: hacd <main> <ts> <contract> <NAMES> <certfile>
  REAL_EXIT = 127

新（引擎 10-26）：
  hacd: contract=T1A8kaeWqK6wMUw5UMHCA6tMQ1iBdECyH count=1 names=MVUUBA cert=none(#3000)
  --- TransferHacdTo(PayableHACD) ---
  unsigned_tx_hex = 03006ad6e9a700…
  selfcheck       = OK
```

**影响**：按当前树打包，`wallet-app` 与 `android-app` 的 HACD 存入/赎回**全部失败**。PC 端表现为 `exit 127` 加英文 panic 文本（`runTxbuild` 的 `close` 处理器把它 reject 成原始 stderr），Android 端经 JNI 返回 `[ERROR] usage: …`。

**同时失准的三处**：

| 项 | 现状 |
|---|---|
| `SHA256SUMS.txt` | 仍记录旧哈希 `f15a19ef…`（与实际文件一致，但对应的是**不支持 #3000 的旧版**） |
| `wallet-app/dist/` | 内含旧二进制与旧 `hacds_oracle.py` |
| 发布文档 | 未提示「引擎需 2026-10-26 之后构建」 |

> **已确认的口径**：旧二进制不会随新版发布、也不支持新合约。因此这不构成**线上**资金风险，但它是一个**必须闭环的构建门禁**：只要有人在当前树上执行 `npm run dist` 或 `gradlew assembleRelease`，产出的就是一个 HACD 功能全坏的安装包。

**修复**：

1. 把 `target/release/hacds_txbuild.exe` 复制进 `wallet-app/bin/`；
2. 用 `android-app/build-engine.sh` 重新构建两个 `.so`；
3. 重算 `SHA256SUMS.txt`；
4. 删除或重建 `wallet-app/dist/`；
5. **加一条构建门禁**（见 §4 建议）。

## 3. High 级发现

### H-6 【High·文档即部署依据】`发行参数-正式.md` 的源码核对表 **12 处行号全部错位，且一处取值写成旧地址**

**位置**：`hacds_exchange/发行参数-正式.md:107-108, 181, 201, 298-305`

该文档开头自述：「本文件是 #3000 的 AssetCreate 与 ContractDeploy **唯一参数依据**」。逐条核对结果：

| 文档声称 | 实际该行内容 | 正确行号 |
|---|---|---|
| `:70` SCORE_SCALE | **空行** | `:96` |
| `:75` TREASURY | `//` | `:101` |
| `:111` RENT_PERIOD | `// 年区块数 365×86400/300` | `:149` |
| `:118` PERIOD_NEW | `const REF_WINDOW : u128 = 300` | `:156` |
| `:128` HACDS_SERIAL | 注释段 | `:165` |
| `:178` HACDS_SUPPLY | `// ---- 储备与赤字 ----` | `:215` |
| `:182` BURN_ADDR | `// ---- AMM 与借贷风控 ----` | `:223` |
| `:2282` 无管理员 | **空行** | 见下 |

**最严重的一条**（`:304`）：

```
HacdsDeFi3000.fitsh:182   BURN_ADDR    = VKNwXFFM...（= 合约地址）
```

文档在核对表里把 `BURN_ADDR` 写成了**旧版 #2000 的地址**，而源码 `:223` 是：

```fitsh
const BURN_ADDR : address = T1A8kaeWqK6wMUw5UMHCA6tMQ1iBdECyH
```

`BURN_ADDR` 是**首注死份额的接收地址**（LP 份额永久锁死处）。合约注释本身已郑重警告「写错会把 LP 死份额记到别的地址，而 tx 里没人能动那个地址的账」。文档却在这里给出了错值。

**影响**：部署前若照此核对，会得出「源码与文档不一致」的困惑；若反过来照文档"修正"源码，会把死份额地址改成旧合约 —— **不可逆**。

其余两处行号引用（`:181` 无管理员、`:201` BURN_ADDR 说明）同样指向空行/错误位置。

**修复**：用脚本重算行号并更新；`BURN_ADDR` 行改为 `T1A8kaeW…`。建议**删除行号、只保留常量名**，因为每次改合约都会让行号失效（本次即因合约新增 59 行注释导致全线漂移）。

### H-7 【High·未修】索引器三处注入/污染面仍在

上一轮 M-2、M-5 未修复。终审复测确认全部仍可利用：

**① `caller` 未 URL 编码 → 可向本地节点注入 query**（`hacds_indexer.py:_call`）

```python
u = f"{self.node}/query/contract/sandboxcall?contract={self.contract}&function={fn}&caller={c}"
```

`c` 来自台账地址，而台账地址可经 `/watch/add` 任意指定。实测构造：

```
caller = "1Q9hgjaG…&function=balance_hac&params=evil"
→ 解析出 function = ['loan_health', 'balance_hac']  （重复参数）
→ params 被注入
```

**② `/watch/add` 仍只判空**（`:707-712`）

```python
a = (qs.get("address") or [""])[0].strip()
if not a: return ...400
IDX.add(a, ...)                      # 不校验 base58check、不限长、不限量
```

**③ `match_contract_fn` 仍用子串匹配，且三个只读视图仍计入借款**

```python
LOAN_FNS = ["loan_borrow", ..., "loan_status", "loan_debt_of", "loan_coll_of"]  # 视图仍在
for sig, name in LOAN_SELECTORS.items():
    if sig in hx:          # 任意位置子串，且不校验目标合约
        return name
```

**可利用性**：任何人调一次 `loan_status(自己)` 就会把自己写进观察名单；任何 calldata 含这 4 字节的交易都会被误记。

**修复**：`urllib.parse.quote(c, safe="")`；`add()` 前用已有的 `_addr_to_21()` 校验；从 `LOAN_FNS` 移除三个视图（或单列 `probe` 不计入 `calls`）；selector 按 `09 14 01 <sig4> ee` 结构定位。

## 4. 注释 ↔ 代码一致性专项（本次指定重点）

这是本轮的主要工作量。共核对 **6 处**注释与实现不符，其中 2 处会误导运维。

| # | 位置 | 注释声称 | 代码实际 | 影响 |
|---|---|---|---|---|
| **C-1** | `HacdsDeFi3000.fitsh:2582` | 「索引器判读规则（见 **`/health`** 输出）」 | 索引器在 **`/backing`** 端点；`/health` 只返回 `ok/head/watched` | 运维按注释调 `/health` 会拿不到任何覆盖率数据 |
| **C-2** | `HacdsDeFi3000.fitsh:2702` | bit8：「`tot:hac/tot:ds` 归零但对应侧仍有余额」 | 只检查 `tot:hac:`，**完全没有查 `tot:ds`** | 注释承诺了不存在的检查；hacds 侧总量归零不会触发告警 |
| **C-3** | `HacdsDeFi3000.fitsh:2697` | bit3：「def > providers×5%（**`DEF_ALERT_BPS`**）」 | 该常量**不存在**；代码硬编码 `> 500` | 搜常量名会一无所获；改阈值时找不到定义处 |
| **C-4** | `发行参数-正式.md:304` | `BURN_ADDR = VKNwXFFM…` | 源码是 `T1A8kaeW…` | 见 H-6，**最高优先** |
| **C-5** | `hacds_indexer.py:858` | 启动日志 `serving on **0.0.0.0**` | 实际监听 `args.host`（默认 `127.0.0.1`） | 运维看日志会以为已对外开放，实际没有；反向也可能误判防火墙问题 |
| **C-6** | `wallet-app/contract-errors.js:105-113` | `PayableHACD` 错误表含「缺少证书流」「证书流长度不足」「证书校验失败」 | #3000 钩子**不读证书**；且表内 `5:` **重复两次** | 见下 |

**C-6 详情（有实际用户影响）**：

```js
PayableHACD: {
  5:  '该钻石名无法读取基因（名字非法或链上不存在）',
  1:  '合约已暂停',
  2:  '钻石名单格式不合法',
  3:  '缺少证书流（既无 Message 也无 Blob）',      // #2000 遗留，#3000 不会返回
  4:  '证书流长度不足（每颗需 126 字节）',          // 同上
  5:  '证书校验失败（验签不过 /…/ 名字对不上）',    // ← 键 5 重复，覆盖了第一条
  48: '单笔只能 1 颗 HACD（VM resource 限制）',
}
```

- **重复键**：JS 对象字面量后写者胜，所以 `5` 实际映射到「证书校验失败」。而 #3000 的 `5` 真实含义是**「该钻石名无法读取基因」**（合约 `PayableHACD` 里 `if sc == 0 { return 5 }`）。用户在存入失败时会被告知"证书校验失败"——一个 #3000 根本不存在的概念。
- **死映射**：`3` / `4` 在 #3000 的 `PayableHACD` 中不会返回（实测返回码集合 = {0, 2, 5, 48, 53, 54}），保留它们无害但也无意义；真正缺的是 `53`（供应上限）与 `54`（覆盖率闸门）的文案。

**修复**：删除 `3`/`4`，删除重复的第二个 `5`，保留「无法读取基因」并补 `53`/`54`。

**C-3 的具体验证**：

```bash

                    ↑ 仅在注释里出现，无 const 定义

$ grep -n "mul_div(d, 10000, prov) > 500" HacdsDeFi3000.fitsh
2720:            if mul_div(d, 10000, prov) > 500 { r = r + 8 }   ← 硬编码
```

**一致的项（已核实，无需处理）**：

- `self_check` 的 bit 值与实现**一一对应**（2/4/8/16/32/128/256/512 全部实测命中），且已明确标注 bit0/bit6 未实现及原因；
- 结算不变式注释（`Σ due + Σ loan:coll == tot:ds`，不含 `amm:ds`）已校正，与 `add_liquidity`/`remove_liquidity` 的 `total_add(1,…)`/`total_sub(1,…)` 一致；
- 索引器 `save()`/`load()`/`sync()` 的注释与实现一致（`mkstemp`、锁内快照、解析失败 `SystemExit`）；
- keeper `_value_len` 注释与实现一致，且**实测四种键型的批次上限精确吻合**：


## 6. 新增代码专项：`hacds_build_server.py`（297 行）

这是本轮唯一全新组件，构成新的公网攻击面（经 Worker 反代）。审查结论：**设计正确，两处输入校验缺失**。

### 6.1 做对的部分（已核实）

| 项 | 实现 |
|---|---|
| 不签名/不广播/不持私钥 | 只 `subprocess.run([txbuild, "call", …])` 产出未签名体 |
| 函数白名单 | `ALLOWED_FNS` 11 项，注释要求与合约 `function external` 列表核对 |
| 参数校验 | 长度 ≤1024、项数 ≤16、字符集 `^[0-9A-Za-z:,._\-]+$` |
| 地址校验 | `ADDR_RE` base58 字符集 + 长度 26–36 |
| 限流 | 单 IP 30 次/分（内存 deque + 锁） |
| CORS | 来源白名单（非 `*`） |
| 兜底拒签 | 显式检查输出中不得出现 `signed_tx_hex`，否则返回 500 |
| 无 shell | `subprocess.run` 列表形式，无 `shell=True` |
| 默认监听 | `--host 127.0.0.1` |
| 错误脱敏 | 不回显完整 stderr（避免泄露服务器路径） |

### 6.2 缺陷

**M-18 【Medium】`gasMax` 未校验，非法值导致 500**

```python
gas_max = int(req.get("gasMax") or 99)      # 不在 try 内
```

实测：

```
gasMax="abc"  → ValueError: invalid literal for int()   （未捕获 → 500）
gasMax="-1"   → -1      → 写入 env["HACDS_GAS_MAX"]="−1" → 引擎 parse 失败
gasMax="999"  → 999     → 超出 u8 范围
gasMax="0"    → 0       → 引擎显式 panic（"gas_max byte 0 gives zero budget"）
```

后果：单请求即可让处理线程抛未捕获异常（`ThreadingHTTPServer` 下只影响该请求，但返回 500 且无诊断信息）。**不构成资金风险**（服务不持私钥），属可用性与健壮性。

**M-19 【Medium】`fee` 完全未校验**

```python
if fee: env["HACDS_FEE"] = str(fee)
```

任意字符串进 `HACDS_FEE`。引擎 `Amount::from(&fee_str).unwrap_or_else(|e| panic!(…))` 会 panic → `build_failed`。同样无资金风险（未签名体，费用由用户钱包签名时确定），但错误信息不友好。

**修复（合计 6 行）**：

```python
try:
    gas_max = int(req.get("gasMax") or 99)
except (TypeError, ValueError):
    return self._send({"error": "bad_gasMax"}, 400)
if not (1 <= gas_max <= 99):
    return self._send({"error": "bad_gasMax", "detail": "gasMax 取值 1–99"}, 400)
if fee is not None and not re.match(r"^\d+:\d+$", str(fee)):
    return self._send({"error": "bad_fee", "detail": "fee 形如 0:248"}, 400)
```

- 服务自身**无鉴权**，安全性完全依赖 `--host 127.0.0.1` + Worker 反代。若运维改成 `0.0.0.0` 直连，则任何人都能免费调用构建服务（消耗 CPU，但不耗资金）。
