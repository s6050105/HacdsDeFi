## 1. 结论

**发现 1 项 Blocker、3 项 High、5 项 Medium。核心问题出在新引入的存储键上。**

### 1.1 最严重：`tot:ds` 与 `tot:ds:` 是两个不同的键

记账函数写的是 **`tot:ds:`**（带尾冒号），但有 3 处代码读的是 **`tot:ds`**（不带）：

| 位置 | 用途 | 后果 |
|---|---|---|
| `coverage_ds()` | 覆盖率分母 | **永远少算用户债权 → 覆盖率被高估** |
| `PayableHACD` 供应上限 | `claims + mint > HACDS_SUPPLY` | **供应闸门被放宽，可能超发** |
| `rent_keys_group(6)` | 续租清单 | **真正的 `tot:ds:` 键从未被续租** |

第三条会在 **约 34.7 天**后让 `tot:ds:` 过期，届时**所有 HACD 存入/赎回、AMM 加减池、抵押划转全部整笔回滚**——合约不可升级，无人能救。

这个缺陷**在测试网无法被发现**：测试网 1 块/秒，10,000 块 = 2.8 小时，而测试只覆盖了功能闭环，没有验证续租（G 阶段测的是只读视图）。

### 1.2 第二严重：根目录的部署产物是超限的旧文件

```
hacds_exchange/HacdsDeFi3000.deploy.json      17,259 B  > 16,384 上限  ❌
hacds_exchange/_build_v30/HacdsDeFi3000.deploy.json  16,201 B         ✅（修复 B-1 后实测编译）
```

两份字节码**不同源**（ACTVIEW 调用点 1 处 vs 3 处）。用根目录那份部署会直接失败。
而 `发行参数-正式.md`、`编译说明-v3000.md` 里引用的都是**不带路径的文件名**，极易拿错。

### 1.3 三项 High

| 编号 | 问题 |
|---|---|
| H-1 | `tot:ds:` 未被续租（见 1.1，单列） |
| H-2 | 发布树落后开发树 840 行：发布树仍是"FitSH + 内核"双实现，开发树已统一内核 |
| H-3 | 测试报告声称的 15,936 B / `opt_v2/` 版本**已不存在**，当前源码未被那批测试覆盖 |

### 1.4 正面确认（本轮实测）

- **合约能编译**，16,201 B（修复 B-1 后），在 16,384 上限内，余 183 字节。
- **官方自检通过**：`verify_build.py` 确认 nonce、BURN_ADDR、ACTVIEW 调用点全部一致。
- **内核差分测试通过**：119 个用例，rv64im 内核与参考实现逐条一致。
- 上轮 4 项阻断与全部注释不一致项**均已修复且未回归**。
- 单颗与批量评分**共用同一内核**，"存赎评分漂移"在结构上已消除。

## 2. 详细发现

### B-1（Blocker）`tot:ds` 键名笔误导致三处功能失效 —— ✅ **已于 2026-11-12 修复**

**证据**：

```fitsh
// 记账函数的键（:752 / :766）
function total_add(kind, delta) {
    var sfx = self.kind_suffix(kind)   // kind=1 → "ds:"
    var key = "tot:" ++ sfx            // → "tot:ds:"   ← 带冒号
```

```fitsh
// 唯一的显式读点（:2389）
if self.ld_u128("tot:ds:") == 0 {      // ← 带冒号，正确
```

```fitsh
// 三处误用（:523 / :1051 / :2294）
var claims = self.ld_u128("tot:ds") + self.ld_u128("amm:ds")
...
k = k ++ "tot:ds"                      // 6 字节，而真实键是 7 字节
```

**穷举验证**：源码中全部聚合键字面量共 36 个，其中「真实存在但不在续租清单」的只有两个：

```
amm:lastout (11B)  ← 同笔交易内写后即读，过期只多付一次 recover 租金（gas 成本）
tot:ds:     (7B)   ← 核心账本键，过期 = 核心功能全停
```

**影响推演**：

1. `coverage_ds()` 分母少算 `tot:ds:` → 覆盖率虚高 → `COVERAGE_MIN_BPS` 闸门失效；
2. `PayableHACD` 的 `claims` 少算 → 供应上限实际被放宽，理论上可超发；
3. `rent_keys_group(6)` 续租的是不存在的 `tot:ds`，真实键不在清单 → **34.7 天后过期**。

**为什么测试网没发现**：测试网 1 块/秒，10,000 块租期仅 2.8 小时；测试报告 G 阶段只测只读视图，未覆盖续租。

**为什么前三轮审计没发现**：这个笔误存在于**#3000 的每一个版本**：

| 版本 | `tot:ds`（错） | `tot:ds:`（对） |
|---|---|---|
| 开发树（当前） | 3 处 | 1 处 |
| 发布树 /d/hacds-v3000 | 3 处 | 1 处 |
| `_archive_20261026` baseline | 3 处 | 0 处 |

前三轮审计聚焦在「资金流向、私钥、权限、注入」，没有做过**键名拼写的穷举一致性检查**。本轮通过穷举全部 36 个键字面量才发现。

**修复**（已实施，3 处）：

```fitsh
// :523 coverage_ds()
var claims = self.ld_u128("tot:ds:") + self.ld_u128("amm:ds")

// :1051 PayableHACD
var claims = self.ld_u128("tot:ds:") + self.ld_u128("amm:ds")

// :2294 rent_keys_group —— 移到 klen==7 组
if klen == 7 {
    k = k ++ "tot:ds:"        // 7 字节
    ...
}
```

> **已实施并验证**：三处改为 `tot:ds:`，`rent_keys_group` 中该键从 `klen==6` 移到 `klen==7`。
> 重新编译：**16,201 B**（余 183 字节），`verify_build.py` 自检通过，键长自检全匹配。

### M-1（Medium）根目录 `deploy.json` 超限且与源码不同源

见 §1.2。建议**删除根目录那份**（或改名为 `HacdsDeFi3000.deploy.json.old`），只保留 `_build_v30/`，并在文档中统一写全路径。

### M-2（Medium）`REDEEM_LP_BPS` 已成死常量，但赎回费仍依赖它与 `LP_BPS` 相等

```fitsh
const LP_BPS      : u128 = 8000
const REDEEM_LP_BPS : u128 = 8000       // 定义后只在注释里出现
...
self.charge_fee_amm(1, fee)   // 赎回费用的是 charge_fee_amm，即 LP_BPS
```

赎回费通过 `charge_fee_amm` 实现，等价性依赖 `LP_BPS == REDEEM_LP_BPS`。现在两者都是 8000 所以正确，但 `REDEEM_LP_BPS` 已无代码引用——**改它不会有任何效果，改成别的值也不会报错**。这是典型的"看似可配、实则失效"陷阱。

**修复**：删除 `REDEEM_LP_BPS`，在 `charge_fee_amm` 旁注明"赎回费复用本函数，比例由 LP_BPS 决定"。

### M-3（Medium）官网仍无 CSP

四个页面 + Worker + `_headers` 均无 `Content-Security-Policy`。纯静态站风险有限，但这是**需要用户签名交易的站点**，且上轮（M-9）已提出未修。

### M-4（Medium）源码内联内核的栈余量警告

编译输出：

```
Warning: kernel 'score_sum': only 7542 B of stack remain between the guard
and the output region; deep recursion or large frames may trap — raise `// calc: mem_kib`
```

`mem_kib` 注释写 14、`score_sum.rs` 里是 16、编译实际用 16 KiB。注释与实现不一致，且余量告警未被处理或记录。

### M-5（Medium）真实 IP 仍硬编码在客户端默认值

`43.251.101.101` 出现在 keeper 默认值、PC 钱包、Android 三处，随公开仓库发布。这是旧审计遗留项，配合"客户端直连明文 HTTP"构成实际风险。

### M-6（Medium）README 措辞与实现不符

发布树 README：「私钥永不落盘明文、**不出子进程**」。
实际实现是 `env.HACDS_SIGN_KEY_HEX = sessionKeyHex` —— 私钥**确实进入子进程的环境块**，同用户权限的进程可读取。

准确表述应为：「私钥不落盘、不进 argv」，并注明环境变量传递的残余风险。
