# Hacash 多签钱包 —— 使用说明

面向 HacdsDeFi 金库托管的实操手册。工具是 `tools/multisig.py`。

---

## 0. 先理解一件事：Hacash 没有「多签地址」类型

比特币有 `2-of-3` 这种原生地址类型。**Hacash 没有。**

Hacash 的多签靠 **P2SH（Pay-to-Script-Hash）** 实现：

```
多签地址 = SCRIPTMH 地址 = base58check( 0x05 ++ ripemd160( sha3(锁脚本) ) )
```

地址本身只是「一段脚本的哈希」。谁能动用这个地址，完全取决于那段脚本写了什么。
脚本里用 `sigset_at_least([候选人...], N)` 检查「本交易上至少 N 个候选人签了名」。

**关键推论：地址由脚本内容唯一决定。脚本改一个字节，地址就完全不同，
而且旧地址里的钱再也取不出来。** 所以脚本要在生成时就定死。

---

## 1. 三条必须记住的规则

### 规则一：返回值 0 才是成功（与多数链相反）

Hacash VM 的约定：

| 返回值 | 含义 |
|---|---|
| `0` / `nil` / `false` | ✅ 成功 |
| **`true`** | ❌ **失败** |
| 任何非 0 整数 | ❌ 失败 |

源码：`vm/src/machine/entry.rs:165 check_vm_return_value`

所以脚本必须写成「签名够 → 返回 0」，**不能**返回 `true`。
写成 `return sigset_at_least(...)` 会变成「签名够了反而转不出去」。

本工具的 lockbox 用 `1 - cond` 做取反，保证这一点。

### 规则二：签名必须写进交易体，不能放 witness

Hacash 的 Type-3 交易，签名集合 D 由三部分并集决定：

```
D = main
  ∪ 各 action 的 req_sign
  ∪ RequiredSigners(0x0414) 里列的地址
```

而且 `verify_type3_signatures_exact` 要求交易里的 SignW2 **精确等于 D**。

所以动用多签时，交易里除了 `P2SHScriptProve(46)`，**必须**再带一个
`RequiredSigners` 列出全部候选人。

**列了不签也没关系** —— `sigset_at_least` 只看「至少 N 个签了」，
不是「全部都要签」。这是 M-of-N 能成立的关键。

### 规则三：main 必须是普通私钥地址

多签地址（SCRIPTMH）**不能**当交易的 main —— main 要付手续费，必须能签名。

```
✅ main = 1H3sFZ...（普通地址，付手续费）
   addrlist = [main, 多签地址, 收款地址]
❌ main = 39vFan...（多签地址）
```

源码：`protocol/src/facts.rs:77 main_address_findings`

## 2. 生成多签

```bash
# 2-of-3：三个候选人，任意两个签名即可动用
python tools/multisig.py create \
    --keys 1H3sFZ53HzNVUVN97mjpC9JT8s2PqKMyRu,\
1MzNY1oA3kfgYi75zquj3SRUPYztzXHzK9,\
1AVRuFXNFi3rdMrPH4hdqSgFrEBnWisWaS \
    --threshold 2 \
    --out vault
```

输出：

```
地址   : 39vFanu6nPgLpGqGGJ4AwJ7VFNMqqMYLdW
规则   : 2-of-3
lockbox: 85 字节
  221500b00ccab4...460b2546a1ee
root   : 3381cb81e4bbf5e9bbcc8491e8cf95091e1aa6b7bf258613ebc035a5960b06ac
写入   : vault.json
```

**`vault.json` 不含任何私钥**，只有公钥地址和 lockbox。
它可以公开、可以备份多份、可以发给任何需要往这个地址打钱的人。

候选人地址必须都是 **PRIVAKEY 类型**（普通私钥地址）。多签/合约地址不能当候选人。

### 常用变体

```bash
# 只看地址，不写文件
python tools/multisig.py address --keys A,B,C --threshold 2

# 看等价的可读 fitsh 源码（审阅用）
python tools/multisig.py lockbox --keys A,B,C --threshold 2

# 反汇编已有 vault，复核地址是否被篡改
python tools/multisig.py dump --vault vault.json
```

## 3. 验证（重要）

```bash
python tools/multisig.py selftest
```

自检包含 6 组，其中两组是**硬证据**：

| 组 | 验证内容 |
|---|---|
| 3 | 本工具生成的 lockbox 与真实 fitsh 编译器**逐字节一致**（地址相关段） |
| 5 | 拿**主网真实存在的** P2SH 脚本复现出它的地址 `3FmXz2VHLju...` |

第 5 组的脚本来自 `vm/src/rt/bytecode.rs:754` —— 那是主网高度 768358 起
真实上链、被全网验证过的 P2SH 脚本。能复现它，说明地址派生逻辑正确。

> 附带结论：**P2SH 在主网早已启用**，不是未来的功能。

## 4. 往多签地址存钱

普通转账即可，收款地址填 `vault.json` 里的 `address`。
对方不需要知道这是多签。

**建议流程**：先转 `0.001 HAC` 进去，然后立刻走一遍第 5 节的转出，
确认全流程通了，再存大额。

## 5. 从多签地址转出（需要本地构建一次）

转出需要构造包含 P2SH 证明的交易。这部分用 Rust 工具：

```bash
cd <hacash_fullnode>
cargo build --release -p testkit --bin hacds_p2sh
```

然后：

```bash
python tools/multisig.py spend \
    --vault vault.json \
    --main  1H3sFZ53HzNVUVN97mjpC9JT8s2PqKMyRu \
    --to    1MzNY1oA3kfgYi75zquj3SRUPYztzXHzK9 \
    --hac   0.001 \
    --nonce 1 \
    --p2sh-tool <上面构建出的 hacds_p2sh 路径> \
    --out spend.hex
```

输出的交易体里有：

- `sign_digest` —— 所有签名人签的是**同一个** digest
- `signer_set` —— D 的完整列表（含顺序）
- `unsigned_tx_hex` —— 未签名交易体

### 收集签名

把 `sign_digest` 发给 `threshold` 个候选人，每人用自己的私钥签这个 digest，
得到 65 字节签名（`r||s||recovery` 或对应格式）。

然后把签名按 `signer_set` 的**地址顺序**填进交易的 SignW2 段，再广播。

> ⚠ 本节流程已实现并通过结构校验，但**尚未在实链完整验证**。
> 首次务必用 0.001 HAC 走通：存进去 → 转出来 → 确认到账。

## 6. 用于 HacdsDeFi 金库

你现在金库是单一冷钱包地址（`TREASURY` 常量硬编码在 #3000 合约里）。

**如果想换成多签金库，必须在部署合约之前决定** —— 部署后合约不可改，
`TREASURY` 会永久指向旧地址。

流程：

1. 用本工具生成 3-of-5 或 2-of-3 多签（候选人是 3~5 个独立冷钱包）
2. 把 `vault.json` 的 `address` 填进 `HacdsDeFi3000.fitsh` 的 `TREASURY` 常量
3. 重新编译、部署

代价：每次从金库提款都需要凑够 N 个签名，手续费和操作复杂度上升。
收益：单个私钥丢失或被盗不再意味着资金全损。

---

## 7. 安全注意事项

- **`vault.json` 不含私钥**，但丢失它等于丢失地址定义。多备份。
- **lockbox 不可修改。** 想改阈值或换人 = 新建一个地址，旧的作废。
- **候选人地址顺序影响地址。** 把 `A,B,C` 改成 `B,A,C` 会得到不同地址。
  本工具保持输入顺序，不做排序 —— 所以**输入顺序要记录在 vault.json 里**（已记录）。
- **别在联网机器上生成候选私钥。** 本工具只处理公钥地址，不碰私钥。
- **取反逻辑不能省。** 如果哪天有人建议「简化成 return sigset_at_least(...)」，
  记住那会导致签名足够时交易失败。
